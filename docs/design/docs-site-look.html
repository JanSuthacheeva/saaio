saaio.dev Look

The real pages saaio-site builds from README.md and docs/repository.md, restyled. Each one is a live page in a frame: scroll it, hover the nav and tables, use the copy buttons, flip the theme with its sun or moon. Pick the page, theme and width below.

What changes from the first version

  • Header: sticky and translucent, blurring the page behind it. It holds the wordmark with the version, a wide search button with ⌘K, Docs and Changelog links, the theme toggle and GitHub. On a phone it shrinks to menu, name, search, theme and GitHub.
  • Left nav by section: Getting started, Guides, Reference and Project. On a phone it slides in as a drawer over a dimmed page.
  • Right rail: "On this page" follows the section you're reading and links to edit the page on GitHub. Below 1240px it moves into the page as a card, and the page's own list of sections shows there instead.
  • Page head: the section name in the accent, a 42px title, and the first paragraph set as a lead.
  • Sections: each ## heading opens with a hairline and shows a # link on hover. A pager to the previous and next page closes each page.
  • Code blocks: a head with the language and a Copy button that turns into "Copied". Shell and TOML comments are dimmed.
  • Callouts: Note, Tip, Important, Warning and Caution, each with an icon in a tinted square. The two on this page are examples; the Laravel-style rewrite will place the real ones.
  • Home: the README with a larger title and lead, and its feature list as cards.
  • Motion: 150ms color and fill transitions on hover, the drawer sliding in, and the pager card lifting 1px. All of it is off when the device asks for reduced motion.

Questions before I build it

  1. Sections in the nav come from docs/README.md: its one table becomes four headed tables (Getting started, Guides, Reference, Project), which read just as well on GitHub. Is that grouping right? Recommended
  2. Depth without shadows. Your design system says no shadows anywhere. Here the depth comes from layered fills, borders, the blurred header and a blurred backdrop behind search. Keep it that way, or allow one soft shadow under the search panel and the phone drawer?
  3. Two departures from the tokens: body text at 17px instead of 18px (docs pages carry tables and code, and 18px felt heavy), and a 10px radius on large blocks (code, tables, callouts, cards), keeping 6px for small ones. Fine?
  4. Search is drawn here as a mock. The real modal is Pagefind's, themed with the same colors, so it will be close, not identical.
