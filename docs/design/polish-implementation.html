flow ui Polish Implementation

1. Decision recap

Approach A: a new ui/focus.rs draws the one focus look (the theme's ui.selection fill plus a ▌ in its ui.accent, so every theme gets its own matching focus), and a shared Dialog widget in dialog.rs draws every dialog (dim behind, padding, title in the border, keys under a rule). A new ui/hints.rs fits key hints into any width and greys out keys that do nothing. The board's detail panel shows the last answer under the decisions, and the steps move into its header (8a).

Decided in review: build all nine findings. The sidebar shows from the start, holding only the master (Solo goes). Focus looks the same everywhere, dialogs included. Findings: review, approaches: page.

/// One key and what it does; `active` false draws both faint, for a key that does nothing now.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Hint {
    pub key: &'static str,
    pub label: Cow<'static, str>,
    pub active: bool,
    /// Kept when the row is too narrow: esc and ? stay as the others go.
    pub kept: bool,
}

impl Hint {
    pub fn new(key: &'static str, label: impl Into<Cow<'static, str>>) -> Hint;
    pub fn inactive(self) -> Hint;
    pub fn kept(self) -> Hint;
}

/// The hints that fit `width`, three columns apart: whole hints are dropped from the right, the
/// kept ones last; never a cut word.
pub fn line(hints: &[Hint], width: usize, theme: &Theme) -> Line<'static>;

Draws every box over a session in one frame.

/// A box over the session: the screen behind it dimmed, the title in its border, one row and two
/// columns of padding, and its keys under a rule that joins the border.
#[derive(Debug)]
pub struct Dialog<'a> {
    pub title: &'a str,
    /// Right of the title in the border, faint: where a new flow starts.
    pub aside: Option<String>,
    /// The border's color: rule for a notice, waiting for a question, blocked for a failure.
    pub border: Style,
    pub body: Vec<Line<'a>>,
    /// Rows the body takes beyond its lines, for a widget that draws into it (new flow).
    pub body_rows: u16,
    pub body_width: u16,
    pub keys: Vec<Hint>,
    pub theme: &'a Theme,
}

impl Dialog<'_> {
    /// The box centered in `area`, a little above the middle, clamped to it.
    pub fn area(&self, area: Rect) -> Rect;
    /// Where the body goes inside `area(area)`: inside the padding, above the key rule.
    pub fn body_area(&self, area: Rect) -> Rect;
}

impl Widget for Dialog<'_> { fn render(self, area: Rect, buf: &mut Buffer); }

/// Every key behind C-space.
pub fn help(theme: &Theme) -> Dialog<'static>;
/// A pane whose process is gone: for a worker (its name) what to do with its flow, else the master.
pub fn not_running(status: &PaneStatus, worker: Option<&str>, theme: &Theme) -> Option<Dialog<'static>>;
/// A worker pane flow ui has no session for.
pub fn no_session(theme: &Theme) -> Dialog<'static>;

render dims all of buf.area, the whole frame, so no caller dims for itself. That replaces app/draw.rs:154.

6. Conventions followed

  • Noun modules with one job: focus.rs and hints.rs, like fit.rs (text in columns) and rail.rs. Functions don't repeat the module name: focus::mark, hints::line (CLAUDE.md, Structure).
  • Widgets as structs with impl Widget, like Sidebar (sidebar.rs:168) and NewFlowView (newflow/view.rs:25). Dialog is one too.
  • Left and right on one row through fit::split (fit.rs:5), as the sidebar's rows already do (sidebar/rows.rs:126). Cards stop painting over it with set_span.
  • App stays I/O free. folded() is a query like areas() (app.rs:156), and the resize effect is the one on_resize already sends (messages.rs:161).
  • The look is pinned by golden files, rewritten with FLOW_UPDATE_GOLDEN=1 (app/tests/golden.rs:6) and read line by line in review.
  • Deviation: Dialog::render dims the whole buffer rather than its area. A widget normally draws only into its area, but the dim is the point of a modal, and doing it here keeps every caller from repeating it.

7. Test seams

  • focus: unit tests on a Buffer: fill on every cell, bar only in column 0, symbols kept, and colors taken from the palette for terminal, flow and flow-light.
  • hints: unit tests: everything fits; drops from the right; kept hints last; inactive drawn faint; never a cut word; zero width.
  • Dialog: unit tests for area and body_area (padding, clamping), and that the rule joins the border with ├ ┤.
  • layout: existing tests without Solo; App::folded in app/tests/panes.rs, both width and the C-space b override.
  • cards: a name cut before its label at 30 columns; mode dropped when it does not fit; blocker in text style.
  • detail: the answer's end kept; no answer, no heading; steps under the header.
  • sidebar: Mark per row (focus, peek, changed); took 2h; tasks-only column; empty rows with no workers.
  • Golden: every view rewritten and checked by eye, plus new narrow-board (96 columns), empty-board, new-flow-agent (focus on agent) and stop-unfinished.
  • E2E: a scratch FLOW_HOME in a separate tmux server at 150×44 and 96×30, the same screens as the review, compared by eye.

8. Assumptions

  1. The rail threshold is 110 columns. Below it the agent gets 88 columns instead of 54 at 96 wide.
  2. C-space b overrides the width until the next C-space b. A resize does not reset the choice.
  3. The peek and a just-changed row get the fill without the bar (focus::light). Only one row ever has the bar.
  4. The title row's needs-you bar goes, because the state glyph next to the name already says it.
  5. Ages read 3m on cards as in the sidebar, and finished flows read took 2h.
  6. Every dialog border is in rule color, except a question (waiting) and a failure (blocked). The title sits in the border.
  7. The last answer shows its end when it is too long, because the end is usually the question or the result.
  8. The rail drops the master's always-accent 0 and marks it like any focused row.

9. Open questions

  1. Inactive keys: do they stay visible in faint, so nothing moves, or go away? I recommend faint, as gitui does. The review said the same.
  2. The board card frame: with the accent box gone, the selected card is a filled block with a bar. Should unselected cards keep a faint rounded box so the grid still reads as cards? I recommend no box. The fill makes the selected card clear, and the empty space already separates the cards.
