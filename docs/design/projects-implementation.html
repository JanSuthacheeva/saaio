One flow per project: shared slots and an overview of every project

new modified unchanged

1. Decision recap

Approach A: every store registers itself in the shared folder ~/.local/state/flow; flow start claims its slot as a file in ~/.local/state/flow/slots/ under a lock held for milliseconds, before setup, and a claim only counts while its flow is unfinished.

Decided: a registry (stores can live anywhere), 20 slots across all projects, the overview in flow status --all and in flow ui's board.

3. Units

src/registry.rs new

Which stores exist: one file per store in the shared folder, named by a hash of its root, holding the root.

/// The shared folder: $XDG_STATE_HOME/flow or ~/.local/state/flow, whatever FLOW_HOME says.
pub struct Registry { root: PathBuf }
impl Registry {
    pub fn locate(xdg_state: Option<PathBuf>, home: Option<PathBuf>) -> Result<Registry>;
    pub fn root(&self) -> &Path;
    /// Writes stores/<fnv1a of the root> when it is missing; cheap enough for every command.
    pub fn register(&self, store: &Store) -> Result<()>;
    /// Every registered store whose folder still exists, sorted by its project name; a vanished one is dropped.
    pub fn stores(&self) -> Vec<Store>;
}
/// A store's project name: its folder's name (".../projects/shop" -> "shop"), "default" for the shared root.
pub fn project_name(store: &Store, registry: &Registry) -> String;

src/slots.rs new

Hands out slots 1-20 so no two unfinished flows in any project share one.

pub const MAX_SLOTS: u8 = 20;   // moved from launch.rs, raised from 9

/// slots/<n>: which flow in which store took slot n.
#[derive(Serialize, Deserialize)]
pub struct Claim { pub store: PathBuf, pub flow: String }

pub struct Slots { dir: PathBuf }   // <registry root>/slots
impl Slots {
    pub fn at(registry: &Registry) -> Slots;
    /// Under an exclusive flock on slots/.lock (released on return): the lowest slot that is neither in
    /// `held` nor claimed by a flow `live` says is unfinished, written as this flow's claim; None when all
    /// 20 are taken.
    pub fn claim(&self, claim: &Claim, held: &[u8], live: impl Fn(&Claim) -> bool) -> Result<Option<u8>>;
    /// Gives a claim back when flow start fails after claiming.
    pub fn release(&self, slot: u8, claim: &Claim) -> Result<()>;
}

4. Data

  • ~/.local/state/flow/stores/<16 hex> - the store's root path, one line. Written by any flow command.
  • ~/.local/state/flow/slots/<n> - {"store": "...", "flow": "<id>"}; slots/.lock - empty, only flocked.
  • flow status --all --json: {"version": 1, "now": ..., "projects": [{"name": "shop", "root": "...", "board": {<the existing Board>}}]}. The single-project --json is unchanged.
  • Flow logs: unchanged. The slot still lives in the Workspace event.

5. Call chains

a. flow start takes a slot

  1. main::start -> launch::flow_name(...), then Store::create(Started): id
  2. start -> held_slots(registry, now): Vec<u8> (every store's unfinished flows)
  3. start -> Slots::claim(&Claim { store, flow: id }, &held, |c| claim_is_live(c, now)): Option<u8> - flock, scan slots 1-20, write slots/<n>, unlock
  4. start -> launch::workspace_for(repo, name, slot, agent) -> workspace::create_worktree -> run_hook(Setup) -> Store::append(Workspace)
  5. None free: Store::remove(id), Failure "all 20 slots are in use" (help: flow status --all, flow clear in the project that holds them). Worktree fails: Slots::release, Store::remove(id), the git error.

b. The overview

  1. flow status --all -> Registry::stores() -> per store Store::logs -> fold::views -> fold::board -> view::Projects
  2. -> output::status_all(&projects, full) (TOON) or Projects as JSON
  3. flow ui: a on the board -> Effect::Run(Job::Overview) -> thread runs <exe> status --all --json -> App::on_ran parses Projects -> BoardView { projects: Some(..) }; again every 2 s while open
  4. An unreadable store becomes a warning line, the others still show; a failed job keeps the last overview and shows a notice.

6. Conventions followed

  • File operations in their own unit with temp-dir tests, like store.rs; the fold stays the only way to read state.
  • fnv1a for a stable file name from a path, as client::socket_path already does.
  • flow ui gets data through a background job running the flow binary, like Job::Start / Job::Remove (ui/mod.rs run_job).
  • Warnings for unreadable logs, as status does today.

7. Test seams

  • Registry: temp shared root; register twice is one file; a vanished store is dropped; project names.
  • Slots::claim: lowest free; held and live claims skipped; a dead claim reused; all taken is None; two threads claiming at once get different slots.
  • tests/cli.rs: two projects (two FLOW_HOME, one XDG_STATE_HOME) start flows and get slots 1 and 2; flow status --all lists both with their project.
  • output::status_all, BoardView with projects: snapshot rows.

8. Assumptions

  1. The registry lives in the default store's folder (~/.local/state/flow), which is also a store; it is registered as "default".
  2. Every flow command registers its store, so stores appear as soon as they are used once.
  3. Flows started before this change hold their slot through their log; held_slots counts them, so no claim file is needed for them.
  4. The project name is the store folder's name; two stores with the same folder name get "name (2)".
  5. The dialog's slot preview stays per project (it can be off by one; flow start decides).
  6. The overview in flow ui refreshes every 2 s while open, by running the CLI; nothing changes in flow server.
  7. flow start's help drops "in a tmux window".
