1. Decision recap

A new mod, flows, draws the board in the band above the prompt, not in a pane: a tab row (All plus one tab per flow), an overview of every flow on All, and a compact detail on a flow's tab. It runs flow status --json every 2 s while shown, turns the board into a band model in a pure module, and draws it with Buttons so digits, vim keys and the engine's focus ring do the navigation.

  • Decided with the prototype: band over pane (full width, digits from an empty prompt, every layout); tabs inside the band; vim-like keys; visual polish.
  • Prototype findings folded in: an overview of cards with pills (your request after the first version); a flow's tab fits the band so the tabs never scroll away; colour by progress, not per phase (per-phase hues collapse in Noctalia); Box has no flexBasis (whole-percent width instead); the title and pills keep their width with flexShrink={0}.

The look

Real Claude Code 2.1.299 with the prototype mod, your Noctalia theme, a narrow 99-column window. Everything is theme keys, so /theme recolours it. Rounded pill ends are Nerd Font glyphs (U+E0B6, U+E0B4).

  • Tab row: lightning mark and "flows", then All and one tab per flow; the active tab is a filled claude pill, the rest dim text with a state mark (● in the state tone for flows that need you, ✓ done). A warning pill on the right counts flows that need you ("2 need you", just "2" below 110 columns).
  • Cards (All): rounded border, in the state tone when the flow needs you, inactive otherwise; 3 columns from 120 columns, 2 from 78, else 1. Each card: name and a state pill; a phase rail ● ── ● ── ◉ ── ○ with the current phase named; a task bar with count and age; one line: the blocker, or the agent's task, or the request.
  • A flow's tab: a hero card - name, state pill, mode pill, "started 1h ago"; the request; the phase stepper with durations next to the task bar; the blocker after a ! or ? pill. Under it TIMELINE (newest first, ◉ for the latest, 3 rows, j/k scroll) and DECISIONS (last 3, ◆) side by side.
  • Colours by progress: done success, current in the state tone (claude, warning, error), open inactive. State pills: working/delegated claude, waiting warning, blocked and not responding error, done success, ended subtle; text inverseText.
  • Legend right-aligned under the board: h ‹ l › j ↓ k ↑ · 0-9 jump · ctrl+x tab for keys.

4. Data

Board crosses flow -> stdout -> parseBoard (the core's --json contract v1, mirrored, read only). BandView, Navigation and the shown flag are atoms; only the shown flag is stored ($.store). BandModel crosses board.ts -> drawing and is never stored.

5. Call chains

5.1 /flows and /flows shop-221

  1. command.run { args: '' } -> register.show($, !isShown) -> update(isShown); $.store.set(shownKey, shown)
  2. shown -> register.refresh($) -> answer 'Flows shown.'; hidden -> answer 'Flows hidden.'
  3. command.run { args: 'shop-221' } -> show($, true) -> refresh($) -> navigate($, board => open tab of the flow named shop-221)
  4. no such flow -> answer 'No flow named shop-221.' (band shown on All)
  5. session.start -> settings.flowPath = options.flowPath ?? 'flow'; isShown = $.store.get(shownKey) === true; register the command; clock.every(2 s, refresh while shown)

5.2 Refresh every 2 s while shown

  1. clock.every(2_000) -> isShown? register.refresh($) : nothing
  2. refresh -> readBoard($) -> $.process.run([settings.flowPath, 'status', '--json'], { timeoutMs: 5_000 })
  3. throws ENOENT / not found -> { board: previous, problem: { kind: 'missing', path } }
  4. exitCode != 0 -> { problem: { kind: 'failed', message: first stdout line without 'error: ' } }
  5. board.parseBoard(stdout): Board | Problem
  6. Problem (unparsable or version != 1) -> { board: null, problem }
  7. navigation.reconcile(board, current): Navigation -> update($, view, ...) and update($, navigation, ...) -> the band's ui.render runs again

5.3 Drawing the band

  1. ui.render { component: 'AbovePrompt' } -> !isShown or e.props.hasSurvey -> return next(e)
  2. bandId = e.requestId; read view, navigation
  3. view.board null -> drawProblem(view.problem): missing -> 'flow is not installed - cargo install --path ~/projects/flow, or set flowPath'; failed -> its message; unsupported -> 'flow speaks contract v2; update the flows mod'
  4. board.bandModel(board, navigation, e.props.bodyColumns): BandModel -> drawTabs + (drawCards | drawDetail) + drawLegend
  5. beneath = await next(e) -> stacked under the board when it is not empty (Q3)
  6. any throw -> the hook's .catch answers next(e): the band shows what was beneath, never a broken tree

5.4 Keys

  1. digit n (empty prompt, or band focused) -> tab Button (hotkey n) onPress -> navigate($, (b, at) => jumpTo(b, at, n))
  2. h / l (band focused) -> legend Button onPress -> navigate($, (b, at) => stepTab(b, at, -1 | 1))
  3. j / k on All -> navigate(moveCursor) -> focusCursor($) -> $.ui.focus({ requestId: bandId, key: 'row-' + flow.id })
  4. $.ui.focus { deny } (band lost the keyboard) -> ignored; the cursor still moved
  5. j / k on a flow's tab -> navigate(scrollTimeline)
  6. Enter on a focused row -> row Button onPress -> navigate(at => ({ ...at, tab: flow.id, offset: 0 }))
  7. g -> navigate(toTop) (+ focusCursor on All)
  8. o -> openMergeRequest($) -> currentFlow(board, navigation)?.mergeRequest -> $.process.run(openUrlArgv(platform, url))
  9. no MR -> $.ui.toast('shop-221 has no merge request yet'); opener fails -> toast with the URL

  • register.test.tsx - engine tests with a fake flow process (process.run hook) and mock.store: toggle and remembered visibility, refresh, mounted band text for both tabs, digit and letter presses, problems (missing, failed, v2), stacking with a band hook beneath, hidden during a survey.
  • End to end: the real flow with the demo FLOW_HOME in a private tmux, keys pressed, screenshots of both tabs; plus flow report into a flow while the band is open.

8. Assumptions

  1. Polls flow status --json every 2 s only while the band is shown; ages come from the board's now.
  2. The binary is flowPath (setting, default flow); a missing binary shows an install hint instead of the board.
  3. Nine flows get a digit and a tab; more show as +n and are reached with l.
  4. A flow's tab shows the last three decisions and three timeline entries, scrolled with j/k.
  5. Pills, cards and colours as in "The look"; pill ends need a Nerd Font (yours has one; a setting could switch to square ends later).
  6. o opens the flow's merge request in the browser; g goes to the top.
  7. The board yields to surveys; when the selected flow is cleared, its tab falls back to All.
  8. Requires Claude Code 2.1.299+ and the flow binary; tested on the current version only.

9. Decided in review

  • Command: mod flows; /flows toggles the band, /flows <name> opens that flow's tab.
  • Visibility: off until /flows, remembered across sessions ($.store).
  • Sharing the band: the board on top, whatever is beneath (skill-usage) stacked under it.
  • Keys: 0-9 jump; with the band focused h/l tabs, j/k cards or timeline, Enter opens, g top, o merge request.
  • Look: cards and pills as in "The look", built and checked in real Claude Code.
