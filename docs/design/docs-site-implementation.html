1. Decision recap

A feature-gated binary, saaio-site, renders README.md, docs/*.md, CHANGELOG.md and ROADMAP.md into static HTML in the jasu.dev look. It rewrites and checks every link. Pagefind indexes the result. A GitHub Actions workflow deploys it to GitHub Pages at saaio.dev on every push to main, with Cloudflare as DNS only.

Decided: generator A (own), hosting GitHub Pages from Actions, Cloudflare DNS only, theme follows the device with a remembered toggle, the Laravel-style rewrite is a separate flow after this one (2a). Alternative noted: Cloudflare Pages deployed from Actions with wrangler pages deploy would add a preview URL per PR, at the cost of a Cloudflare API token in the repo's secrets.

main.rs

new

src/bin/site/main.rs

The process boundary: parses the arguments, runs the build, prints, and maps the result to an exit code.

/// Builds the saaio.dev docs site from the Markdown in a checkout.
#[derive(clap::Parser)]
struct Args {
    /// The checkout to read.
    #[arg(long, default_value = ".")]
    root: PathBuf,
    /// The folder to write the site to; empty, missing, or an earlier build.
    out: PathBuf,
}

fn main() -> ExitCode;   // 0 built, 1 broken links or an I/O error, 2 usage

On success it prints one line to stdout: built 15 pages and 1 asset into _site. On failure it prints each Broken or the error to stderr.

new

src/bin/site/site.rs

Runs one whole build. Every page renders before anything is written, so a broken link leaves the old output untouched.

pub struct Built { pub pages: usize, pub assets: usize }

pub enum Failure {
    Broken(Vec<Broken>),
    Io(anyhow::Error),
}

/// Reads the pages, renders them, checks every anchor, then writes the site.
pub fn build(root: &Path, out: &Path) -> Result<Built, Failure>;

/// The anchors a link names that its page does not have.
fn missing_anchors(rendered: &[(&Page, Rendered)]) -> Vec<Broken>;

Lists the pages the site publishes, in nav order, and where each one is served.

pub struct Page {
    pub source: PathBuf,   // repo-relative: docs/ui.md
    pub url: String,       // /docs/ui/
    pub title: String,     // the page's first # heading: "The terminal UI"
}

pub struct Pages { list: Vec<Page> }

impl Pages {
    /// README.md, docs/README.md, the docs pages in the order docs/README.md's
    /// table links them, then CHANGELOG.md and ROADMAP.md. Errors when a
    /// docs/*.md other than HANDOVER.md is missing from that table.
    pub fn read(root: &Path) -> anyhow::Result<Pages>;
    pub fn by_source(&self, source: &Path) -> Option<&Page>;
    pub fn iter(&self) -> impl Iterator<Item = &Page>;
}

/// README.md -> "/", docs/README.md -> "/docs/", docs/ui.md -> "/docs/ui/",
/// CHANGELOG.md -> "/changelog/", ROADMAP.md -> "/roadmap/".
fn url_of(source: &Path) -> String;

/// Files under docs/ that are not pages: HANDOVER.md (and docs/design/, not *.md).
const UNPUBLISHED: &[&str] = &["docs/HANDOVER.md"];

render.rs

new

src/bin/site/render.rs

Turns one page's Markdown into its HTML body. It does this through pulldown-cmark's event stream, so the HTML matches what GitHub renders.

pub struct Rendered {
    pub body: String,
    pub outline: Vec<Heading>,      // its ## headings, for "On this page"
    pub anchors: HashSet<String>,   // every heading id
    pub links: Vec<Link>,           // links into other pages, their anchors checked later
    pub assets: Vec<PathBuf>,       // repo files its images show
}

/// Renders with tables, strikethrough, task lists and GitHub alerts (Options::ENABLE_GFM).
/// Headings get Slugs ids, links go through links::resolve, tables sit in a
/// scroll box, a leading # heading is the page title. Errors list every
/// link whose file does not exist.
pub fn render(page: &Page, markdown: &str, pages: &Pages, root: &Path)
    -> Result<Rendered, Vec<Broken>>;

/// The text of the first # heading.
pub fn title(markdown: &str) -> Option<String>;

links.rs

new

src/bin/site/links.rs

Decides where one Markdown link points on the site, using the rule the approaches page set.

pub const REPO: &str = "https://github.com/JanSuthacheeva/saaio";

pub enum Target {
    /// A published page: its url plus "#anchor".
    Page { source: PathBuf, url: String, anchor: Option<String> },
    /// A repo file an image shows, copied to the same path on the site.
    Asset { source: PathBuf },
    /// Any other repo file or folder: {REPO}/blob/main/path or /tree/main/path.
    Repo { url: String },
    /// http(s), mailto: left as written.
    External,
}

impl Target {
    pub fn href(&self) -> Cow<'_, str>;
}

/// Resolves href against the folder of `from`. "#x" is the page itself.
/// A path that leaves the checkout or names no file is Broken.
pub fn resolve(from: &Path, href: &str, image: bool, pages: &Pages, root: &Path)
    -> Result<Target, Reason>;

pub struct Link { pub line: usize, pub href: String, pub target: Target }

pub struct Broken { pub source: PathBuf, pub line: usize, pub href: String, pub reason: Reason }

pub enum Reason { NoFile, NoAnchor, OutsideRepo }

impl fmt::Display for Broken;   // docs/ui.md:12: configuration.md#nope: no heading #nope

/// {{outline}} and {{edit}} ({REPO}/edit/main/{source}) filled in one pass.

The frame has a header (the saaio wordmark, the search box, a theme toggle, a GitHub link), a left nav, the content (data-pagefind-body), an "On this page" outline on wide screens, and a footer (Edit this page, licence). Under 900px the nav folds behind a menu button, and the outline hides under 1200px. site.js holds the toggle (stored in localStorage, read in an inline head script before the first paint), the menu, and new PagefindUI(...).

output.rs

new

src/bin/site/output.rs

Writes the site folder. It's the binary's one place that creates files, behind a local #[allow(clippy::disallowed_methods, reason = "the site is public output, not the user's private files")].

pub struct Output { dir: PathBuf }

impl Output {
    /// Empties `dir`, or creates it. Refuses a non-empty folder without the
    /// .saaio-site marker an earlier build left, so a wrong path can't wipe a repo.
    pub fn create(dir: &Path) -> anyhow::Result<Output>;
    /// "/docs/ui/" -> dir/docs/ui/index.html
    pub fn page(&self, url: &str, html: &str) -> anyhow::Result<()>;
    pub fn file(&self, path: &str, text: &str) -> anyhow::Result<()>;
    pub fn copy(&self, root: &Path, source: &Path) -> anyhow::Result<()>;
}

docs.yml

new

.github/workflows/docs.yml

Builds the site on pull requests and deploys it on main.

on:
  pull_request:
  push: { branches: [main] }
  workflow_dispatch:
permissions: { contents: read }
concurrency: { group: pages-${{ github.ref }}, cancel-in-progress: false }

jobs:
  site:                   # named check, every PR: build + link check
    steps: checkout, rustup toolchain install, rust-cache,
      cargo run --locked --features site --bin saaio-site -- _site,
      Pagefind 1.x: pinned linux-x86_64 tarball, sha256sum -c, pagefind --site _site,
      (main only) actions/configure-pages, actions/upload-pages-artifact (path: _site)
  deploy:
    if: github.ref == 'refs/heads/main'
    needs: site
    permissions: { pages: write, id-token: write }
    environment: { name: github-pages, url: ${{ steps.deployment.outputs.page_url }} }
    steps: actions/deploy-pages

Every action is pinned to a commit with a # vX comment, as in ci.yml.

5. Call chains

saaio-site _site

sequenceDiagram
  participant M as main
  participant S as site
  participant P as Pages
  participant R as render
  participant L as links
  participant O as Output
  M->>S: build(root, out)
  S->>P: Pages::read(root)
  P->>R: title(markdown) per page
  P-->>S: Pages
  loop each page
    S->>R: render(page, markdown, pages, root)
    R->>L: resolve(from, href, image, pages, root)
    L-->>R: Target or Reason
    R-->>S: Rendered or Vec of Broken
  end
  S->>S: missing_anchors(rendered)
  alt any Broken
    S-->>M: Failure::Broken
    M-->>M: print each, exit 1
  else
    S->>O: create(out)
    S->>O: page(url, layout::page(..)) per page
    S->>O: copy(asset), file(css, js), page(404)
    S-->>M: Built
    M-->>M: print summary, exit 0
  end
  1. main -> Args::parse(): Args (a usage error exits 2)
  2. main -> site::build(&args.root, &args.out): Result<Built, Failure>
  3. site::build -> Pages::read(root): anyhow::Result<Pages>, which calls render::title(markdown) per file
  4. per page: site::build -> render::render(page, markdown, &pages, root): Result<Rendered, Vec<Broken>>
  5. per heading: render -> Slugs::next(text): String; per link or image: render -> links::resolve(from, href, image, &pages, root): Result<Target, Reason>
  6. site::build -> missing_anchors(&rendered): Vec<Broken>, which looks up each Target::Page { anchor } in the target's Rendered.anchors
  7. site::build -> Output::create(out), then per page Output::page(&page.url, &layout::page(page, &pages, &rendered))
  8. site::build -> Output::copy(root, asset) per image; Output::file("site.css", CSS), ("site.js", JS), ("404.html", &layout::not_found(&pages))
  9. main prints Built and returns ExitCode::SUCCESS
Error paths A file is missing from the docs/README.md table: Pages::read returns an error. main prints docs/new.md is not listed in docs/README.md and exits 1. A link names no file, or leaves the checkout: render collects Broken { NoFile | OutsideRepo } for every page, so one run lists them all, and exits 1 before anything is written. A link names a heading that doesn't exist: missing_anchors returns Broken { NoAnchor }, and it exits 1. The output reads docs/ui.md:41: flows.md#stacked: no heading #stacked in docs/flows.md. The out folder isn't empty and has no marker: Output::create refuses, and it exits 1 with nothing removed.

  1. GitHub -> docs.yml site on every PR and every push to main
  2. site job -> cargo run --locked --features site --bin saaio-site -- _site: exit 1 fails the check, and nothing deploys
  3. site job -> curl pagefind tarball; sha256sum -c; pagefind --site _site: a checksum mismatch fails the job

A deploy that fails (say Pages isn't set up yet) fails only deploy. The site keeps serving the previous build.

A reader opens saaio.dev

  1. An inline head script runs document.documentElement.dataset.theme = localStorage.theme when one is stored. Otherwise no attribute is set and prefers-color-scheme decides.
  2. The toggle sets data-theme to the opposite of the theme currently shown and stores it (inside try/catch: a blocked storage just doesn't remember).
  3. The search box: site.js -> new PagefindUI({ element: "#search", showSubResults: true }). Results link to /docs/x/#heading. Without JavaScript the box is hidden and the nav still works.

TXT_github-pages-challenge-JanSuthacheevathe code GitHub shows in step 1 below-
  • Proxy off (grey cloud) on every record. GitHub Pages gets its Let's Encrypt certificate only when saaio.dev resolves to its own IPs. With the orange cloud on, Cloudflare answers instead, the certificate is never issued, and "Enforce HTTPS" stays greyed out.
  • SSL/TLS mode: Full (strict). It does nothing for DNS-only records. It's a guard in case the proxy is ever switched on: "Flexible" with Pages' HTTPS redirect makes an endless redirect loop.
  • Delete any record already at @ or www (the registrar's parking ones). If DNS → Records lists a CAA record, keep or add 0 issue "letsencrypt.org".

GitHub

  1. Verify the domain (stops anyone else's Pages site from claiming it): github.com → your avatar → Settings → Pages → Add a domain → saaio.dev. Put the TXT record it shows into Cloudflare, then click Verify.
  2. Repository: JanSuthacheeva/saaio → Settings → Pages → Build and deployment → Source: GitHub Actions.
  3. After this PR merges and the first deploy ran: the same page → Custom domain: saaio.dev → Save. Wait for "DNS check successful", then tick Enforce HTTPS once the certificate is issued (minutes, up to an hour).
  4. Settings → Environments → github-pages: the deployment branch rule is "main" (Pages creates this. Check it, don't widen it).

No CNAME file in the build: with Actions deployment, GitHub ignores it and reads the custom domain from the settings. www.saaio.dev redirects to saaio.dev by itself once both resolve to Pages.

7. Conventions followed

  • A thin entry point that only parses, prints and maps exit codes: mirrors src/main.rs and the CLAUDE.md "main.rs" rule.
  • One responsibility per file, named as nouns (pages, links, slug, output): CLAUDE.md Structure.
  • File creation in one file behind a local allow with a reason: mirrors workspace.rs's git info/exclude exception (CLAUDE.md, clippy.toml:10-18).
  • pulldown-cmark's event stream: mirrors src/ui/markdown.rs:3.
  • Actions pinned to a commit with a version comment, timeout-minutes, permissions: contents: read at the top: mirrors .github/workflows/ci.yml:12-29.
  • Deviation: a second binary in a crate whose rule is "a library with a thin binary". Forced by cargo install --git, which refuses a repo with two packages that have binaries (shown on the approaches page). CLAUDE.md states this.
  • Deviation: the binary doesn't use the saaio library (text::fill would fit, but lib.rs exports only cli). Its own 10-line fill keeps the library's surface closed.

8. Test seams

  • slug: unit tests against GitHub's slugs of real saaio headings (`[ui]` -> ui, saaio --stop -> saaio---stop, repeats).
  • links: unit tests over a tempfile checkout: page, anchor-only, ../examples, folder, image, external, missing, outside the repo.
  • render: unit tests on Markdown strings: heading ids, alert markup, table wrapper, rewritten hrefs, Broken with line numbers.
  • pages: nav order from a scratch docs/README.md; an unlisted page errors; url_of.
  • output: refuses a non-empty unmarked folder, replaces a marked one.
  • layout: every placeholder filled, the current page marked, the outline present.
  • site::tests::the_repository_builds: builds the real checkout (env!("CARGO_MANIFEST_DIR")) into a temp folder and asserts no Broken. This is the link check every PR runs.
  • End to end: build, pagefind --site _site --serve, then look at it in a browser at desktop and phone width, light and dark, and try search and the 404 page.

9. Assumptions

  1. CHANGELOG.md and ROADMAP.md are pages (/changelog/, /roadmap/), the recommendation from question 4.
  2. README.md is the home page as written, the screenshot and install snippet with its --tag v0.2.1 pin included. Pins stay in the Markdown, and the site doesn't fill in a version.
  3. Nav order and membership come from the docs/README.md table, the single list. A page missing from it fails the build.
  4. No syntax highlighting: code blocks render in the jasu.dev code-block style, plain. The Laravel rewrite can add it.
  5. The site is built on every PR and fails it on a broken link, as a new site check (and through cargo test --all-features).
  6. No web fonts: the system sans and mono stacks of the design system.
  7. An "Edit this page" link per page, to GitHub's editor on main.
  8. Pagefind is pinned to the latest 1.x release that's at least two weeks old, checked by SHA-256.
