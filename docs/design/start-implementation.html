flow start: a flow, a worktree, a stack slot and a worker window

1. Decision recap

Approach A: flow start creates the flow, a git worktree of its own and a port slot, runs the repo's optional setup hook in the worktree, then opens a tmux window there running the worker agent from a launch template, with FLOW_ID set. flow clear runs the repo's teardown hook and removes the worktree of a finished flow.

  • Decided: flow makes the worktree; an agent is a command template (Claude Code built in, others in config); flow stays agent- and Docker-agnostic.
  • Docker (your note, tests run inside the container): every worktree gets its own stack. flow hands the setup hook a slot (1-9); the repo's hook turns it into ports (HTTP_PORT=8000+slot), starts the stack and migrates. Compose names a project after its folder, so docker compose exec php ... run in a worktree reaches that worktree's stack. Each project once needs its ports from variables ("${HTTP_PORT:-80}:80").
$ cd ~/projects/php/buzzwoo-ai
$ flow start "SHOP-217 add CSV export"

# .flow/setup in the repo (committed), example
#!/bin/sh
set -e
export HTTP_PORT=$((8000 + FLOW_SLOT))
export DB_PORT=$((33060 + FLOW_SLOT))
docker compose up -d
docker compose exec -T php php artisan migrate --seed

# .flow/teardown
#!/bin/sh
docker compose down -v

4. Data

Workspace is a new event in the private log and a new optional field in the --json board (programs ignore unknown fields; an older flow skips the unknown event). Config is read from the user's config dir, never written.

5. Call chains

5.1 flow start "SHOP-217 add CSV export"

  1. main -> Command::Start -> Config::load(env FLOW_CONFIG, XDG_CONFIG_HOME, HOME) -> config.agent(--agent)
  2. unknown agent -> Failure "no agent named x", help "Agents: claude, ..."; config unreadable -> Failure naming the file and the TOML error
  3. $TMUX unset -> Failure "flow start opens the worker in a tmux window - run it inside tmux"
  4. workspace::repo_root(cwd) -> repo
  5. not a git repository -> Failure "flow start needs a git repository", exit 1
  6. views(store) -> launch::flow_name(request or --name, unfinished names); launch::free_slot(views) -> slot
  7. no slot -> Failure "all 9 slots are in use", help "Run `flow clear` after finished flows"
  8. launch::workspace_for(repo, name, slot) -> workspace::create_worktree(repo, &workspace)
  9. branch or path exists, git error -> Failure with git's line; nothing recorded
  10. store.create(Started) -> id; store.append(id, Workspace { window: None })
  11. workspace::run_hook(repo, Setup, &workspace, launch::hook_env(...)) -> ran / none
  12. hook exits non-zero -> append Blocked "setup failed: <last stderr line>", the window still opens so you can look (assumption 5)
  13. launch::agent_argv(agent, id, name, request) -> launch::window_argv(workspace, name, [FLOW_ID, FLOW_HOME?], agent_argv) -> workspace::open_window -> "@14"
  14. tmux fails -> append Ended, Failure with tmux's line (worktree kept)
  15. store.append(id, Workspace { window: Some("@14") }) -> output::started(flow, setup_ran) -> TOON with help "Run `tmux select-window -t @14` to watch it"

5.2 flow clear with worktrees

  1. clear -> for each finished flow with a workspace: repo = parent of WORKTREES_DIR in the path
  2. workspace::run_hook(repo, Teardown, &workspace, env) (failures noted, clear goes on)
  3. workspace::remove_worktree(repo, &workspace) -> false (uncommitted work) -> kept[n] in the answer with its path
  4. store.remove(id) as today -> output::cleared(names, kept)
  5. the branch stays: it carries the MR

6. Conventions followed

  • Pure planning module and one I/O module, like fold.rs / store.rs; env lookups passed in as arguments, like Store::locate (src/store.rs).
  • AXI output: TOON document with help[], errors as Failure on stdout (src/output.rs).
  • Additive log and contract changes: unknown kinds are skipped by older folds (Event::from_line), new optional JSON fields leave v1 readers working.
  • New dependency: toml for the config (Q4).

7. Test seams

  • launch.rs unit: names (ticket, words, collisions), slots (lowest free, finished flows free theirs, full), paths, every argv exactly, template filling, hook env.
  • config.rs unit: built-in only, a file adding an agent and overriding claude's prompt, a broken file.
  • fold.rs unit: workspace on the view, the last one wins.
  • tests/cli.rs: a real temp git repo, a fake tmux on PATH (prints @14, records its argv), a .flow/setup that writes a file: start, start outside tmux, outside a repo, hook failing, clear removing a clean worktree and keeping a dirty one.
  • End to end: your trial - a real repo in tmux, flow start on a tiny request, the board with /flows in the master, the worker reporting, flow clear.

8. Assumptions

  1. Worktrees live in <repo>/.flow/worktrees/<name> on branch flow/<name>, branched from the current HEAD; .flow/worktrees/ goes into .git/info/exclude, never a tracked file.
  2. Hooks are .flow/setup and .flow/teardown in the repo (committable), run in the worktree with FLOW_ID, FLOW_NAME, FLOW_SLOT, FLOW_WORKTREE, FLOW_REPO.
  3. Nine slots, so at most nine running flows per machine.
  4. The worker window opens in the current tmux session, in the background (-d); FLOW_HOME is passed on when set.
  5. A failed setup hook marks the flow blocked but still opens the window, so you can see and fix it.
  6. Workers run in your default permission mode.
  7. flow clear keeps a worktree with uncommitted work and always keeps the branch.
  8. The name follows the board's rule: ticket key, else the first four words.

9. Decided in review

  • First prompt: /ship-feature {request} (ship-feature exists in agent-skills). It must be installed for Claude Code first: there is no ~/.claude/skills/ship-feature link yet - a prerequisite of the end-to-end trial, asked before it.
  • Command: flow start <request> [--name] [--mode] [--agent] in a git repo inside tmux; flow clear also tears worktrees down.
  • Location: worktrees in .flow/worktrees/, hooks .flow/setup and .flow/teardown, all in the repo.
  • Config: TOML at ~/.config/flow/config.toml, with the toml crate.
