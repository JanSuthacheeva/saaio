saaio - design-code, phase 3 - 2026-11-04 - approach A

One heavy run per project

1. Decision recap

A worker's PreToolUse hook takes the project's turn (an flock on <store>/turns/0.lock) before a listed command runs, waiting and saying so while another worker has it. It hands the locked file to a detached saaio turn watcher, which keeps the turn while any process under the worker's agent runs a listed command.

Decided in phase 2: approach A. It matches on word boundaries, so Sail and docker compose exec lines are caught. A crash releases the turn through the kernel. A background run keeps it until its process ends. The scope is the project now, and the lock folder and the number of lock files are the knobs for a machine-wide limit later.

Review round 1: the person's own config.toml gets [exclusive] enabled, a switch for the whole feature on their machine. The repo says which commands are heavy; the person decides whether their machine takes turns.

Changed since phase 2: Claude Code starts its shells in a new process group (seen in this session: the Bash tool's zsh has its own pgid), so getsid in the hook may not be the agent. Instead the server records each worker pane's agent pid in the store, and the hook checks it is its own ancestor.

src/exclusive.rs new

The commands a repo lists as heavy, and whether a command line runs one (pure).

/// [exclusive] in a repo's config.
#[derive(Debug, Clone, PartialEq, Eq, Deserialize)]
#[serde(deny_unknown_fields)]
pub struct Exclusive {
    /// "artisan test", "pint": one or more words each.
    #[serde(deserialize_with = "commands")]
    pub commands: Vec<String>,
}

impl Exclusive {
    /// The first listed command `line` runs: its words in a row, on word boundaries,
    /// anywhere in the line ("./vendor/bin/sail pint" runs "pint", "pint.json" does not).
    pub fn runs(&self, line: &str) -> Option<&str>;
}

/// Refuses an empty list entry or one that is only spaces.
fn commands<'de, D: Deserializer<'de>>(de: D) -> Result<Vec<String>, D::Error>;

src/turns.rs new

The lock files that are the turns, and who holds one. It is allowed to create files, as slots.rs does through private::options().

/// Who holds a turn: written into its lock file in place, read by those who wait.
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct Holder {
    pub flow: String,    // id
    pub name: String,    // shown to waiters
    pub command: String, // the listed command it runs
}

/// The turns of a scope: `limit` lock files in `dir`.
#[derive(Debug, Clone)]
pub struct Turns {
    dir: PathBuf,
    limit: u8,
}

/// A taken turn: its lock file, open and locked; dropping it releases the turn.
#[derive(Debug)]
pub struct Turn {
    file: File,
}

pub enum Take {
    Taken(Turn),
    /// `holder.flow` already holds one: its watcher covers this run too.
    Own,
    /// Every turn is held; the holder of the first.
    Held(Option<Holder>),
}

impl Turns {
    /// A project's turn: one, in <store>/turns. (A machine-wide scope later: the
    /// shared folder's turns/, with its own limit.)
    pub fn of_project(store: &Store) -> Turns;

    /// Tries every lock file without waiting: Taken with `holder` written in, Own
    /// when a held one names `holder.flow`, else Held.
    pub fn try_take(&self, holder: &Holder) -> Result<Take>;
}

impl Turn {
    /// The locked file, for the watcher's stdin; the lock lives as long as it is open.
    pub fn into_file(self) -> File;
}

src/processes.rs new

The process table as ps prints it, and which processes run under a given one.

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct Process {
    pub pid: u32,
    pub ppid: u32,
    /// Its argv joined by spaces.
    pub command: String,
}

/// Every process: `ps -A -o pid=,ppid=,command=`, with a 1 s deadline
/// (workspace::process::output).
pub fn list() -> Result<Vec<Process>>;

/// `ps` output read; a line that does not parse is skipped.
fn parse(text: &str) -> Vec<Process>;

/// The processes below `root`, children and theirs.
pub fn under(all: &[Process], root: u32) -> Vec<&Process>;

/// True when `root` is `pid` or one of its ancestors.
pub fn descends(all: &[Process], pid: u32, root: u32) -> bool;

src/turn_watch.rs new

When a held turn is let go (pure). The watcher feeds it one look every 500 ms.

/// What one look at the processes found.
#[derive(Debug, Clone, Copy)]
pub struct Look {
    pub agent_alive: bool,
    /// A process under the agent runs a listed command.
    pub runs: bool,
    /// The flow waits on a permission prompt (FlowView.permission).
    pub asks: bool,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Keep {
    Hold,
    Release(Release),
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Release {
    AgentGone,
    RunEnded,
    /// No listed process showed up within GRACE (denied, failed to start).
    NeverRan,
}

/// How long a turn waits for its run to show up; a permission prompt pauses it.
pub const GRACE: Duration = Duration::from_secs(10);

#[derive(Debug)]
pub struct TurnWatch { /* since, seen, quiet looks */ }

impl TurnWatch {
    pub fn new(now: u64) -> TurnWatch;
    /// Hold or release after `look` at `now`; a run ends after two quiet looks in a row.
    pub fn step(&mut self, now: u64, look: Look) -> Keep;
}

src/cli/commands/hook.rs modified

After wait_for_services, a flow's PreToolUse whose line runs a listed command waits for the turn.

/// The longest a tool call waits for its turn, then runs anyway.
const TURN_WAIT: Duration = Duration::from_mins(30);

/// Before a flow's tool call whose `line` runs a command its repo lists: takes the
/// project's turn, waiting (TurnWaiting once, TurnTaken at the end) while another flow
/// has it, and hands it to `saaio turn`. Logs and lets the call run when the config
/// breaks, the agent is unknown, or TURN_WAIT ran out.
fn wait_for_turn(store: &Store, id: &str, line: &str, log: &Log, clock: fn() -> u64);

/// Starts `saaio turn --flow id --agent pid` in a process group of its own, `turn` as its
/// stdin, nothing else open.
fn keep_turn(turn: Turn, id: &str, agent: u32) -> Result<()>;

In run: if config.exclusive.enabled && let Some(line) = adapter.command(&payload) { wait_for_turn(...) } after the services wait. The hook already loads the config (the built-in one when it breaks), so a broken config.toml keeps turns on.

c) The same flow already holds the turn

  1. wait_for_turn -> Turns::try_take(&holder): Take::Own -> return (its watcher sees this run among the agent's processes too)

d) Watcher releases

  1. TurnWatch::step(look { agent_alive: false, .. }): Release(AgentGone) - the worker crashed or its pane closed
  2. TurnWatch::step(look { runs: false, .. }) twice in a row after a run was seen: Release(RunEnded) - finished, killed, or a background run's process exited
  3. TurnWatch::step(look { runs: false, asks: false, .. }) past GRACE, no run seen yet: Release(NeverRan) - log "the turn was not used within 10s"
  4. processes::list fails (ps missing or past its deadline) -> log, count as runs: true until 3 failures in a row, then release
  5. the watcher is killed -> the kernel drops the flock; nothing to clean

e) Errors before a turn

  1. RepoConfig::load: Err (broken toml) -> log "{file}: ..." -> the call runs unheld. saaio start already fails loudly on the same file.
  2. Store::agent: None (a pane an older server opened) or the pid is not the hook's ancestor -> log -> runs unheld
  3. Turns::try_take: Err (folder or file cannot be made) -> log -> runs unheld
  4. keep_turn: Err (spawn failed) -> log -> the turn drops when the hook exits; runs unheld

Every error fails open: a broken turn never stops a worker, and the hook stays silent on stdout as it is today.

6. Conventions followed

  • The hook holds a tool call by polling the store, as wait_for_services does (src/cli/commands/hook.rs:158). Its errors go to server.log through Log (:206).
  • The flock on a file opened through private::options(), with std File::lock / try_lock, mirrors Slots::lock (src/slots.rs:73). No unsafe; no new crate.
  • External commands run with a deadline through workspace::process::output (src/workspace/process.rs:31).
  • Hidden subcommands that run without a store check: Hook, Wait (src/cli.rs:74-92).
  • The services state from events, labels on card and detail: EventKind::Services (src/event.rs:142), cards.rs:288, detail.rs:123.
  • Per-session files in waits/, removed with the flow (src/store.rs:347).
  • Deviation: turns.rs writes into a file it holds open (the holder), instead of write_atomic, because replacing the file would make a second lock.

  • repo_config.rs: unit with temp dirs; branch and exclusive together, missing file, invalid entries.

  • processes.rs: parse, under and descends on fixed text; one test runs list and finds itself.
  • turn_watch.rs: unit, every Release path, grace paused by a permission prompt, the two quiet looks.
  • fold.rs: TurnWaiting and TurnTaken, cleared by Idle and Ended, changes.
  • labels, cards, detail, status: their existing render tests and the golden files.
  • tests/cli/turn.rs: end to end with the real binary: two fake flows in a scratch store; flow A's hook takes the turn while a sleep named pint runs under a fake agent; flow B's hook waits, logs TurnWaiting, and goes on after the process is killed.
  • E2E: a scratch store, two Claude workers in a repo with [exclusive]; one runs a slow listed command in the background, the other's call waits and the sidebar says so.

8. Assumptions

  • Word boundaries: a listed word is not preceded or followed by a letter, digit, _, . or -, so vendor/bin/pint and test:parallel match but pint.json does not. A line that only mentions a command (git commit -m "fix pint") also waits; that's rare and harmless.
  • sail test is caught only when listed: it never contains artisan test. The docs example lists it.
  • Waiters are not served strictly first come; each polls every 500 ms.
  • Every flow session waits, plain sessions included, when its folder's repository lists commands. The master never waits.
  • The sidebar keeps the spinner, its label says waits turn in the muted color, and its third row says after shop-42: pint.
  • A turn whose run never shows up is let go after 10 s; a permission prompt for that call pauses the clock.
  • Only the Bash tool is matched: Claude Code's Bash and Codex's shell. Other tools (an MCP that runs tests) are not.
  • Using a turn needs no repository trust: listing commands can only make calls wait, never run anything.

9. Decided

Approved 2026-11-04 with the recommended answers: a call waits at most 30 minutes, then runs anyway; turn in the JSON and TOON output; [exclusive] enabled defaults to true. The questions as they were asked:

1. How long can a call wait for its turn? I suggest 30 minutes, after which the call runs anyway (logged, and the wait label goes). The PreToolUse timeout rises from 150 s to 33 min for every tool, though only listed commands use it. The alternative is no limit, which needs a timeout of hours. Codex's maximum hook timeout still has to be checked; the first build task verifies it.

2. JSON contract name. FlowView.turn: { command, holder, since } in saaio status --json, and a turn column (empty or waiting) in the TOON output. OK?

3. The switch's default. [exclusive] enabled in your own config.toml. I suggest true: a repo that lists commands already opted in, and a teammate with a big machine turns it off for themselves. With false, nobody waits until they enable it, even in a repo that lists commands. The machine-wide scope would join this section later. Which default?
