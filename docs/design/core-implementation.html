flow: an AXI that records flows and shows where they stand

Changed in this revision: flow is an AXI, since its main user is an agent: TOON output by default, a live home view with no arguments, help[] next steps on every output, structured errors on stdout with exit codes 0/1/2, idempotent flow new, short default fields with --full, flows addressed by name. --json stays for programs (the mod). 1. Decision recap

A new Rust AXI in ~/projects/flow is the only writer of one append-only JSONL log per flow and the only place that folds those logs into what a flow looks like. Agents talk to it in TOON; programs (the Claude Code mod later) read flow status --json. The log stays private.

  • Decided: CLI folds, readers use status output (round 3); files, no daemon; ship-feature keeps phase order and auto mode (round 2); new repo; follow the AXI principles (this round).
  • In this piece: flow (home), flow new, flow report, flow status, flow clear. Later: flow start (piece 5), the mod (3, 4), auto mode and a skill stub (6), a flow setup hook for ambient context (AXI principle 7, with piece 6).

2. Structure overview

new existing later piece

event.rs, fold.rs, view.rs and output.rs are pure; store.rs owns every file operation; main.rs is the only place that reads the environment and the clock and writes stdout. Everything uses event.rs; those edges are left out.

3. Units

src/main.rs

newedge

Responsibility: parses the command line, runs one command, prints one TOON (or JSON) document and exits 0, 1 or 2.

Collaborators: Store, fold, output; environment (FLOW_ID, FLOW_HOME, XDG_STATE_HOME, HOME), clock, stdout. Uses Cli::try_parse() so a clap error becomes a TOON error on stdout with exit 2. Commands return Result<Document, Failure>; nothing prompts.

src/event.rs

newpure

Responsibility: defines what can be reported and how one event is one JSON line in the log.

src/store.rs

newI/O

Responsibility: reads and writes flow logs and heartbeats under one directory.

Collaborators: std::fs, uuid. Appends use OpenOptions::append and one write_all per line, so two writers in one worker (the mod and a skill) never interleave a line. Errors are anyhow with context; main.rs turns them into a Failure.

src/fold.rs

newpure

Responsibility: turns one flow's events into its view, views into the sorted board, and a name or id into one flow.

Collaborators: event, view. Rules in 4. Data - fold rules.

src/view.rs

newcontract

Responsibility: the derived types; serialised whole as the --json contract programs depend on (types in 4. Data).

src/output.rs

newpure

Responsibility: shapes every agent-facing answer: lean TOON documents with aggregates, explicit empty states, truncation hints and help[] next steps.

Collaborators: view, serde_toon_format (encodes small private serde structs per document). Help texts keep fixed flags and use placeholders (<name>) for runtime values.

Cargo.toml, README.md, CLAUDE.md, .gitignore

new

Crate and binary flow, edition 2024. Dependencies: anyhow, clap (derive, env), serde (derive), serde_json, serde_toon_format, uuid (v4); dev: tempfile. README: install, commands, the TOON views, the --json contract. CLAUDE.md: build/test commands and the module map, as mdterm/CLAUDE.md does.

4. Data

Event crosses CLI -> file (private, versioned for forward compatibility). Board crosses CLI -> stdout as --json for programs (public contract, VIEW_VERSION). TOON documents are built from the same views in output.rs with fewer fields (AXI: minimal default schemas). Times are Unix ms.

After the events: a heartbeat older than SILENT_AFTER_MS turns any state but done and ended into not-responding; a flow that never sent a heartbeat never becomes not-responding (harnesses without the mod). The current step's duration runs until now. Repeated reports fold to the same view, so a retried flow report is harmless (AXI: idempotent mutations).

5. Call chains

5.1 Every invocation: parse, run, print, exit

  1. main -> Cli::try_parse(): Cli
  2. Err(clap::Error) -> --help / --version print as clap does, exit 0; any other -> Failure::usage(&error).to_toon() on stdout, exit 2 (unknown flags fail loudly)
  3. Store::locate(env FLOW_HOME, env XDG_STATE_HOME, env HOME)
  4. no HOME and no override -> Failure "cannot find a state directory", help "Set FLOW_HOME to a directory", exit 1
  5. run(cli, &store, now_ms()): Result<Document, Failure> -> command None -> home(), else the command's fn
  6. Ok(doc) -> print doc.text(), ExitCode 0; Err(failure) -> print failure.to_toon(), ExitCode failure.code

5.2 flow new --name shop-221 --request "..." --mode auto

  1. new_flow -> views(&store, now) -> fold::resolve(&views, "shop-221")
  2. an unfinished flow of that name -> output::created(flow, existing: true) - nothing written (idempotent)
  3. else Event::new(now, EventKind::Started { name, request, mode }) -> store.create(&event): id -> fold::fold(&id, &[event], None, now)
  4. create fails -> Failure::from_io: "could not create flow in ~/.local/state/flow/flows: Permission denied", exit 1
  5. output::created(&flow, existing: false) -> flow, id, existing, help: "Run `export FLOW_ID=<id>` in the worker", "Run `flow report phase design` when design starts"

5.3 flow report blocked "Task 5: ..." (and heartbeat)

  1. main -> Command::Report { flow: --flow or $FLOW_ID (clap env), event: ReportEvent::Blocked { reason } }
  2. flow None -> output::skipped(): "skipped: no flow id", help "Set FLOW_ID or pass --flow <name>", exit 0 (Q3)
  3. report -> views(&store, now) -> fold::resolve(&views, &flow): &FlowView
  4. None -> Failure "no flow named shop-999", help "Run `flow` to list the flows", "Run `flow new --name shop-999 --request <text>` to start it", exit 1
  5. event.into_kind(): Some(kind) -> store.append(&flow.id, &Event::new(now, kind)) (texts cut to 500 chars) | None (Heartbeat) -> store.beat(&flow.id)
  6. io error -> Failure::from_io, exit 1
  7. fold::fold(&id, &store.events(&id)?, store.last_beat(&id)?, now) -> output::reported(&flow): help by state - blocked: "Run `flow report working` once the block is resolved"; waiting: "... once answered"; done: "Run `flow clear` after the MR is merged"

5.4 flow, flow status [<name>] [--json] [--full]

  1. views(&store, now): per store.ids() -> store.events(id), store.last_beat(id) -> fold::fold(...)
  2. events() fails for one flow -> left out, and the document carries warnings[n]: "cannot read <id>: <error>" (data stays on stdout)
  3. fold::board(views, now): Board
  4. json -> Document::Json(board.to_json()) (named: a board with only that flow) - nothing truncated
  5. no command -> output::home(&board, bin path with $HOME as ~, &warnings)
  6. status without name -> output::status_list(&board, &warnings, full); empty -> "count: 0", "flows: none tracked", help "Run `flow new ...`"
  7. status <name> -> fold::resolve(&board.flows, name) -> output::status_detail(flow, now, full)
  8. resolve None -> Failure "no flow named ...", exit 1

5.5 flow clear

  1. clear -> views(&store, now) -> those with view.is_finished() -> store.remove(&view.id) each
  2. output::cleared(&names): "cleared: 2", names[2], help "Run `flow` to see what is left"; nothing finished -> "cleared: 0" (idempotent)
  3. remove fails -> Failure with the id, the rest stays removed, exit 1

6. Conventions followed

  • AXI principles (axi.md): TOON output, minimal default fields, truncation with --full, aggregates (count, needs_you), definitive empty states, errors on stdout with exit 0/1/2, idempotent mutations, no prompts, home view with bin and description, help[] next steps, concise --help. The home view mirrors lavish-axi --help's shape.
  • Flat src/, one module per concern, declared in main.rs: wordstamp/src/main.rs:1-7.
  • clap derive with doc-comment help and #[command(version, about)]: wordstamp/src/main.rs:21-22.
  • anyhow inside, with context: wordstamp/src/main.rs:14.
  • Inline #[cfg(test)] mod tests per module: wordstamp/src/align.rs:177.
  • CLAUDE.md with build commands and a module map: mdterm/CLAUDE.md.
  • Pure core and one I/O module, like plan-progress's pane.ts / register.tsx split.
  • Deviation: main returns ExitCode, not anyhow::Result as in wordstamp (main.rs:59), so errors land on stdout as TOON with the AXI exit codes.
  • Deviation: no dirs crate - dirs::state_dir() is None on macOS, so Store::locate resolves XDG itself and takes its inputs as arguments.

7. Test seams

  • event.rs - unit: round trip per kind; text cut at 500 chars; from_line None for broken JSON, version 2, unknown kind.
  • fold.rs - unit, the heart: every row of the fold rules, idempotent repeats, durations with a fixed now, not-responding only with a heartbeat, board order, resolve by id, by unfinished name, by finished name.
  • store.rs - unit on a tempfile::TempDir: create/append/events, append to a missing flow fails, beat/last_beat, ids, remove; locate precedence.
  • output.rs - unit, exact TOON for: home, empty status, list with truncation hint, detail, created (new and existing), reported per state, skipped, error, usage error.
  • tests/cli.rs - integration on the built binary with FLOW_HOME in a temp dir: new twice (same id), reports, status --json parsed with serde_json, home, unknown flag exits 2 with TOON on stdout, missing flow exits 1, clear.
  • End to end: an agent in a scratch repo told only "use flow to report your progress" finds its way from the home view and help lines alone.

8. Assumptions

  1. Ids are UUID v4 (reused later as the worker's --session-id); agents mostly use names, and an id works wherever a name does.
  2. flow new with the name of an unfinished flow returns that flow (existing: true) instead of a second one.
  3. Report texts are cut to 500 chars when stored; list views cut to 80 with a hint; --json and --full never truncate.
  4. Unknown event kinds and broken lines are skipped when folding, so an older flow reads a newer log.
  5. "Not responding" after 90 s without a heartbeat, only for flows that ever sent one.
  6. TOON via serde_toon_format 0.2 (TOON v4.1, a young crate); if it misencodes, output.rs gets a small encoder for the three shapes used (scalars, inline arrays, tabular arrays) behind the same functions.
  7. --json keys are camelCase for the TypeScript reader; TOON keys are snake_case like lavish-axi's (needs_you).
  8. Ambient context (AXI principle 7) is not in this piece: in Claude Code the mod's board provides it; a flow setup hook and skill stub come with piece 6.

9. Decided in review

  • Command surface as proposed: flow, flow new, flow report <event>, flow status [<name>] [--json] [--full], flow clear; flow from --flow <name|id> or $FLOW_ID.
  • Logs in $FLOW_HOME, else $XDG_STATE_HOME/flow, else ~/.local/state/flow.
  • No flow id: flow report answers skipped: no flow id with exit 0.
  • Ship mode: implement-plan builds it.
  • AXI: TOON by default, home view, help[], errors on stdout, exit 0/1/2, idempotent mutations; --json for programs.
