flow ui themes: the design's colors, and Noctalia, live

1. Decision recap

Approach A: ~/.config/flow/theme.toml, as the design's Theme artboard shows it, picks a base with extends and overrides keys; flow ui checks it and the file it extends once a second and repaints when either changes.

Decided: built-in bases terminal (today), flow (the design's dark palette) and flow-light; a Noctalia template in dotfiles-v2 writes ~/.config/flow/themes/noctalia.toml on every theme change, so extends = "noctalia" follows Noctalia live.

src/ui/theme.rs modified

Turns fourteen named colors into the styles every widget draws with; holds the built-in palettes.

/// The colors a theme file names, by its keys; Color::Reset is "default", the terminal's own.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Palette {
    pub background: Color, pub panel: Color, pub selection: Color, pub rule: Color,
    pub text: Color, pub strong: Color, pub muted: Color, pub faint: Color, pub accent: Color,
    pub working: Color, pub waiting: Color, pub blocked: Color, pub done: Color, pub ended: Color,
}
impl Palette {
    /// "terminal" (today's look), "flow" (the design's dark colors), "flow-light"; None for another name.
    pub fn named(name: &str) -> Option<Palette>;
    /// The color of one key ("accent", "working", ...); None for a key flow does not know.
    pub fn get(&self, key: &str) -> Option<Color>;
    /// Sets one key; false for a key flow does not know.
    pub fn set(&mut self, key: &str, color: Color) -> bool;
}
pub struct Theme { pub ui: UiTokens, pub state: StateTokens, pub glyphs: Glyphs, pub palette: Palette }
pub struct UiTokens { /* as now */ pub background: Style }   // added: the ground every cell is painted on
impl Theme {
    pub fn builtin() -> Theme;                       // from_palette(Palette::named("terminal"))
    /// strong = bold in `strong`, key = bold in `strong`, bar = `text` on `panel`, selection = `selection` behind.
    pub fn from_palette(palette: Palette) -> Theme;
    /// Text on a solid pill: the background, or black where the background is the terminal's.
    pub fn on_solid(&self) -> Color;
}

src/ui/theme_file.rs new

Reads theme.toml and the theme it extends, and tells when either changed.

pub const THEME_FILE: &str = "theme.toml";
pub const THEMES_DIR: &str = "themes";
/// How many extends a theme may follow before flow gives up (a loop, most likely).
const EXTENDS_LIMIT: usize = 4;

/// The theme in `dir`: theme.toml over what it extends, a built-in name or themes/<name>.toml;
/// the built-in terminal theme when there is no theme.toml. Also every file it read or would read.
pub fn load(dir: &Path) -> (Result<Theme>, Vec<PathBuf>);
/// One file's colors applied over `palette`, in file order so a key can name one set above it.
fn apply(file: &ThemeFile, palette: &mut Palette) -> Result<()>;
/// "#rrggbb", an ANSI index 0-255, "default", or another key of the palette.
fn color(value: &toml::Value, palette: &Palette) -> Result<Color>;

/// Knows the files the current theme came from, by size and time (missing counts too).
pub struct ThemeWatch { dir: PathBuf, stamps: Vec<(PathBuf, Option<Stamp>)>, }
impl ThemeWatch {
    pub fn new(dir: PathBuf) -> ThemeWatch;
    /// The theme again when one of its files appeared, changed or went away; always on the first call.
    pub fn changed(&mut self) -> Option<Result<Theme>>;
}

5. Call chains

a. flow ui starts

  1. main::ui -> config::config_file(FLOW_CONFIG, XDG_CONFIG_HOME, HOME): Option<PathBuf>, its parent is UiEnv.theme_dir
  2. ui::run(socket, env) -> ThemeWatch::new(env.theme_dir) -> ThemeWatch::changed(): Some(result)
  3. ThemeWatch::changed -> theme_file::load(dir): (Result<Theme>, files): no theme.toml gives Theme::builtin(); otherwise read it, follow extends (Palette::named or themes/<name>.toml, at most 4 deep), apply each file from the base up, Theme::from_palette
  4. Err: ui::run keeps Theme::builtin() and calls App::say("theme.toml: <error>"); the notice shows in the border until the next key.

b. Noctalia switches theme while flow ui runs

  1. Noctalia renders templates/flow.toml to ~/.config/flow/themes/noctalia.toml
  2. Within 1 s: ui::run tick -> ThemeWatch::changed(): the stamp of themes/noctalia.toml differs -> theme_file::load(dir) -> Some(Ok(theme))
  3. ui::run replaces its theme and redraws: App::draw(frame, &theme, peek) paints the background, ScreenView draws the pane's default cells in text on background.
  4. Err (a half-written or broken file): the old theme stays, App::say names the file and the error; the next change tries again.

c. You switch to the design's colors

  1. You set extends = "flow" in theme.toml (or ask the master to); the same tick path as b repaints within a second.

6. Conventions followed

  • Change detection by size and time, as StoreWatch (src/server/watch.rs:12), reusing store::Stamp.
  • Files beside config.toml, located like it (src/config.rs:78); TOML read with the toml crate as config.rs does.
  • All tokens stay in Theme (src/ui/theme.rs:5, "so a theme file can replace them later"); widgets keep reading tokens, nothing else changes in them except the pill text.
  • Periodic work on the UI tick, like the peek (TICKS_PER_PEEK, src/ui/mod.rs); the notice line like the board's (App.notice).
  • Deviation: the theme moves from a parameter of ui::run into it, because it now changes while running.

7. Test seams

  • Palette: named palettes exist and match the table; get/set reject unknown keys.
  • theme_file::load: temp dir; no file is terminal; extends built-in and themes/ file; overrides; key references; bad hex, unknown key, unknown base, an extends loop each give an error naming the file.
  • ThemeWatch: first call loads; unchanged gives None; editing the extended file, creating theme.toml and deleting it each give Some.
  • ScreenView, App::draw: a TestBackend frame with the flow palette has background on empty cells and text color on default cells.

8. Assumptions

  1. Without theme.toml flow looks exactly as today (terminal).
  2. A broken theme keeps the last good one and says why; it never stops flow ui.
  3. background paints every cell flow ui draws, including the focused pane's default-colored cells, so Claude's output sits on the theme's ground as in the design. Cells Claude colors itself keep their colors.
  4. The Noctalia template keeps state colors as ANSI, which Noctalia already sets through terminal-sequences; the mapping in the template is yours to change.
  5. Only flow ui reads the theme; the server and the CLI never do.
  6. Once a second is quick enough for a theme change.
  7. On this Mac there is no Noctalia: use extends = "flow" there; "noctalia" would say the file is missing and fall back.
