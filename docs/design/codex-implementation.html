Codex workers and master

1. Decision recap

Approach A: Adapter::Codex passes flow's hooks to every Codex launch as -c hooks.* arguments. You trust them once in Codex's own review, and flow learns each Codex session id from its hooks.

A Codex session cannot wake itself, so news reaches it two ways:

  • Busy: from its synchronous Stop hook.
  • Idle: flow server types it in, but only when the session is idle and no key has gone into that pane for 10 s.

Decided in phase 2:

  • Codex can be the master, chosen with [master] agent = "codex".
  • A new session event holds the session id and transcript path.
  • A Codex peek and an agent row in the new-flow dialog are both in scope.
  • Skills stay agent-agnostic.

a. Start a Codex worker

  1. App -> Job::Start::args(): ["start", req, "--mode", m, "--agent", "codex"]
  2. main::start -> config.agent(Some("codex")): (&str, &Agent), then the Workspace event
  3. Server::refresh -> reconcile -> launch::worker_spec(flow, agent, env): Option<PaneSpec>
  4. worker_spec -> Adapter::Codex.wiring(flow_exe): Vec<String>, spliced in after "codex"
  5. Server::open_worker -> Host::open(spec), then Workspace window = HOSTED
  6. Host::open fails: Blocked "could not start the agent: ..." in the log, so the sidebar shows it.
  7. First run: Codex's hooks review shows in the pane. Until you press t, the hooks do not run and the flow stays in its started state.

b. A Codex hook event

sequenceDiagram
  participant C as codex
  participant M as main::hook
  participant A as codex::translate
  participant F as fold
  participant St as Store
  participant D as deliver
  C->>M: stdin JSON, FLOW_ID
  M->>A: translate(payload, phases)
  A-->>M: [Session, Working | Phase | Waiting | Answer+Idle ...]
  loop each kind
    M->>F: changes(id, events, kind, now)
    M->>St: append when true
  end
  alt UserPromptSubmit
    M->>St: set_busy(flow, true)
  else Stop
    M->>D: worker_news(store, id, now)
    alt news
      M->>St: append Working
      M-->>C: stderr news, exit 2: Codex goes on
    else none
      M->>St: set_busy(flow, false)
    end
  end
  1. codex -> sh -lc "'flow' hook codex" with the payload on stdin and FLOW_ID in its environment
  2. main -> hook(store, config, "codex", Hooked::Flow(id), payload, now): HookOutcome
  3. hook -> Adapter::Codex.translate(payload, phases): Vec<EventKind>
  4. hook -> fold::changes(id, events, kind, now): bool -> Store::append
  5. hook -> Store::set_busy(&Waiter::Flow(id), true) on UserPromptSubmit
  6. On Stop, when !wakes_itself(): hook -> deliver::worker_news(store, id, now). With news, it appends Working and returns HookOutcome { news }, and main prints it and exits 2. Without, it calls set_busy(false).
  7. No FLOW_ID and no --master, bad JSON, or an unknown flow: one stderr line, nothing appended, exit 0. Codex logs it and goes on.

c. Resume a Codex worker

  1. Server::reopen_worker / refresh -> launch::worker_spec(flow, agent, env)
  2. worker_spec -> resume_argv(agent, id, name, flow.session.id): ["codex","resume","01a1..."], then the wiring after "codex"
  3. No session known, because the worker never had a turn: agent_argv, so it starts fresh with the prompt again.
  4. Resume exits non-zero within RESUME_GRACE: open_fresh, as today.

d. The master's message reaches an idle Codex worker

sequenceDiagram
  participant Ma as master (flow send)
  participant St as Store
  participant S as Server tick
  participant D as deliver
  participant H as Host
  participant C as codex
  Ma->>St: append Message
  S->>S: server_delivered(key): Waiter::Flow(id)
  S->>St: busy(waiter)? false
  S->>S: typed_at[key] older than QUIET
  S->>D: worker_news(store, id, now)
  D->>St: set_delivered
  D-->>S: Some(news)
  S->>H: write(key, paste(news))
  H->>C: bracketed paste + Enter

  1. Server::serve -> refresh -> deliver_news() every tick, before refresh's early return
  2. deliver_news -> server_delivered(&key): Option<Waiter>, which looks up the agent's adapter and !wakes_itself()
  3. deliver_news -> Store::busy(&waiter): bool and typed_at[key].elapsed() >= QUIET
  4. deliver_news -> deliver::worker_news(store, id, now): Option<Option<String>>
  5. deliver_news -> Host::write(&key, &paste(&news))
  6. Write fails because the pane is gone: one stderr line. The news is already marked delivered, so it is lost the same way a dead flow wait loses it today.
  7. You type in that pane within 10 s: it waits. If text is left unsent in Codex's prompt, the news is appended after it.

e. Codex as the master

  1. Server::open_master -> Config::master_agent(): ("codex", &Agent)
  2. open_master -> MasterRecord::spec(fresh, agent, env, &instructions, wake, store.master_session()): PaneSpec
  3. spec -> Adapter::Codex.instruct(&instructions.text) + master_wiring(flow_exe, wake), so it runs codex -c ... [resume <sid>]
  4. codex -> flow hook codex --master -> hook(.., Hooked::Master, ..), then Store::set_master_session(session_id) and set_busy(Master, ..)
  5. On Stop with wake: hook -> deliver::master_news(store, flows), which exits 2 with the news. Idle: Server::deliver_news with Waiter::Master.
  6. [master] agent names no agent: Host::fail(Master, "no agent named X"), as today.

f. Peek at a Codex worker

  1. PeekCache::refresh(flow) -> peek::transcript_of(flow, claude_home): Option<(PathBuf, Format::Codex)>
  2. PeekCache -> peek::tail(file, max, Format::Codex) -> parse_codex(text, cut): Vec<PeekLine>
  3. No session yet, a missing file, or a .jsonl.zst rollout: an empty peek, as for a Claude worker without a transcript.

6. Conventions followed

  • Codex's hooks() mirrors claude_code::settings (src/adapter/claude_code.rs:38): one handler per event, exec of the flow binary, synchronous, a 10 s timeout.
  • The wiring is spliced right after the program, as in launch::worker_spec (src/launch.rs:138) and MasterRecord::spec (src/server/master.rs:100).
  • Translation tests are table tests over recorded payloads in src/adapter/fixtures/codex/, as in fixtures/claude-code/.
  • Only changes are appended, through fold::changes (src/fold.rs:39). A repeated session adds no line.
  • News bookkeeping stays in waits/ (src/store.rs:213-245). deliver.rs is what main::worker_news was (src/main.rs:394), moved so the server can call it.
  • The dialog row copies the type row (src/ui/newflow.rs:66-120): Tab moves to it, and h/l and space cycle it.
  • Deviation: the server writes into a PTY on its own, which HANDOVER rejected for Claude. It is limited to adapters that cannot wake themselves, and guarded by busy and QUIET.
  • Deviation: the built-in Claude master gets master.md as text through --append-system-prompt instead of -file, so both harnesses take instructions one way.

7. Test seams

  • codex::translate: table tests over Codex payloads recorded with the real CLI.
  • codex::hooks and toml_string: every event runs the exe, the result parses as TOML, and multiline text survives.
  • Adapter::instruct, wakes_itself and wiring: unit tests per variant.
  • fold: session sets view.session, and changes is false for a repeat.
  • launch::resume_argv and worker_spec: {session} is filled, and a missing session falls back to a fresh start.
  • deliver: tempdir Store tests. News is taken once, and a second call finds none.
  • config: the built-in codex agent, [master] agent, and worker_agents without master.
  • master.rs spec: a Codex master gets its instructions and hooks, and a missing session starts it fresh.
  • server: a fake agent (cat) with adapter = "codex". A message is typed only when the pane is not busy and quiet, using an injected QUIET.
  • peek::parse_codex: a recorded rollout fixture.
  • newflow: the agent row shows with two agents and adds --agent. Plus a golden screen of the dialog.
  • tests/cli.rs: flow hook codex on Stop with a pending message exits 2 with it on stderr. Without one it exits 0, silent.

8. Assumptions

  1. Codex's SessionEnd reason is always "other", so a Codex worker never logs ended from a hook. You end it with C-space Q or flow remove.
  2. Plan-mode and async questions (request_user_input) are invisible to hooks. They read as working until Stop.
  3. plan-progress is a Claude Code mod, so a Codex worker shows no task bar.
  4. A Codex subagent is spawn_agent, which maps to delegated with its description. The field name will be confirmed from a recorded fixture.
  5. -c options before resume apply to the resumed session. This will be checked in the end-to-end run.
  6. Codex rollouts older than 7 days are compressed to .jsonl.zst and show an empty peek.
  7. FlowView.session is additive, so VIEW_VERSION stays. An old flow binary reading a log with session reports that flow as unreadable until it is updated.
  8. The agent row in the new-flow dialog lists every agent but master, and shows only when there are two or more.

9. Decided in review

  1. The agent-skills get linked into ~/.agents/skills through dotfiles-v2 as the last task, before the end-to-end run. Their content stays agent-agnostic.
  2. Codex is signed in again, so payloads are recorded from the real CLI.
