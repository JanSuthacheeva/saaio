Codex workers and master

Revision 2: after merging main

2026-10-16. Codex facts re-checked at openai/codex@6ae8b8a (latest release 0.163.0). Its hooks, CLI, TUI and rollout code have not changed since the first read.

  • New file layout. Every unit moved to main's library structure:
    • the hook command is now cli/commands/hook.rs;
    • the launch code is launch/pane.rs;
    • the server is split into server.rs, conn.rs and panes.rs, and typing news gets its own server/news.rs;
    • the shared adapter helpers go to adapter/answer.rs and adapter/calls.rs;
    • peek splits into peek/claude.rs and peek/codex.rs.
  • Already on main. deliver.rs and Document::Wake (exit 2 with news on stderr) exist. The plan reuses them and only adds deliver::master_news_now, the same lookup without the 2 s settle.
  • Plain sessions. A plain Codex session gets the report hooks only, through plain_wiring. It gets no worker prompt and no news. The dialog's agent row applies to plain sessions too.
  • Protocol. FlowView.session changes the Board that postcard sends, so PROTOCOL_VERSION goes from 3 to 4. VIEW_VERSION stays 2, because the JSON change is additive.
  • New Codex details.
    • spawn_agent has no description, so delegated shows the first line of its message.
    • Bash's tool_response is a plain string, which is what the merge-request match reads.
    • Rollout outputs can be arrays of items.
    • A bracketed paste plus \r submits safely.
  • New and set aside: codex queue. Codex 0.163.0 can start a turn on an idle thread with codex queue --thread <id> --message, but only through its shared daemon. A session started with -c overrides, which our hooks need, runs its own embedded server, and queue refuses that. Server typing stays. HANDOVER notes queue as the replacement once the daemon takes per-session hooks.
  • E2E. Runs go on a scratch FLOW_HOME, never on the real store.

1. Decision recap

Approach A: Adapter::Codex passes flow's hooks as -c hooks.* on every Codex launch. You trust them once in Codex's own review. flow learns each session id from the hooks.

A Codex session cannot wake itself, so news reaches it two ways:

  • Busy: from its synchronous Stop hook.
  • Idle: flow server types it in, when the session is idle and no key has gone into that pane for 10 s.

Decided earlier:

  • Codex can be the master, through [master] agent = "codex".
  • A session event goes in the log.
  • The Codex peek and the dialog's agent row are in scope.
  • The skills stay agent-agnostic: an Artifact where the tool exists, lavish otherwise.

5. Call chains

a. Start a Codex worker

  H--)P: Err -> Blocked
  1. App -> Job::Start::args(): [.., "--agent", "codex"] -> commands::start appends the Workspace event
  2. Server::refresh (panes.rs) -> reconcile -> pane::worker_spec(flow, agent, env)
  3. worker_spec -> Adapter::Codex.wiring(flow_exe) (plain: plain_wiring), spliced in after "codex"
  4. open_worker -> Host::open(spec), then Workspace window = HOSTED
  5. Host::open fails: Blocked "could not start the agent: ..".
  6. First run: Codex's hooks review shows in the pane, and nothing is reported until you press t.

b. A Codex hook event

sequenceDiagram
  participant C as codex
  participant K as commands::hook
  participant A as codex::translate
  participant F as fold
  participant St as Store
  participant D as deliver
  C->>K: stdin JSON, FLOW_ID
  K->>A: translate(payload, phases)
  A-->>K: [Session, Working | Phase | Waiting | Answer+Idle]
  loop each kind
    K->>F: changes(id, events, kind, now)
    K->>St: append when true
  end
  alt UserPromptSubmit
    K->>St: set_busy(true)
  else Stop
    K->>D: worker_news(store, id, now)
    alt News
      K->>St: append Working
      K-->>C: Document::Wake: stderr, exit 2
    else Nothing
      K->>St: set_busy(false)
    end
  end
  1. codex -> sh -lc "'flow' hook codex" -> cli::run -> commands::hook::run(args, env, clock)
  2. run -> hook(store, config, Adapter::Codex, &Hooked::Flow(id), &payload, now)
  3. hook -> Adapter::translate -> fold::changes -> Store::append
  4. hook -> Store::set_busy(&Waiter::Flow(id), true) on UserPromptSubmit
  5. On Stop: hand_over -> deliver::worker_news. News appends Working and returns Document::Wake(news::for_worker(..)), so main exits 2. Otherwise it calls set_busy(false) and returns Silent.
  6. No FLOW_ID and no --master, bad JSON, or an unknown flow: one stderr line, nothing appended, Silent.

c. Resume a Codex worker

  1. Server::reopen_worker / refresh -> pane::worker_spec
  2. worker_spec -> resume_argv(agent, id, name, session.id): ["codex", <wiring>, "resume", "01a1..."]
  3. No session yet: the fresh or plain command.
  4. Resume exits non-zero within RESUME_GRACE: open_fresh, as today.

  1. Server::serve -> deliver_news() every tick, before refresh's early return
  2. deliver_news -> server_delivered(&key): Option<Waiter>: the agent's adapter, !wakes_itself(), not plain
  3. deliver_news -> !Store::busy(&waiter), and typed_at[key] is older than quiet

  5. Write fails: a server.log line. The news is already marked delivered, the same as with a dead flow wait.
  6. You type in that pane within 10 s: it waits. Text left unsent in Codex's prompt gets the news appended after it.

e. Codex as the master

  1. Server::open_master (panes.rs) -> Config::master_agent(): ("codex", &Agent)
  2. open_master -> MasterRecord::spec(start, agent, env, &instructions, wake, store.master_session())
  3. spec -> Adapter::Codex.instruct(&instructions.text) + master_wiring(flow_exe)
  4. codex -> flow hook codex --master -> Hooked::Master: set_master_session(session_id) and the busy marks
  5. Stop with wake: deliver::master_news_now, then Wake(news::for_master(..)). Idle: deliver_news with Waiter::Master.
  6. [master] agent names no agent: Host::fail(Master, "no agent named X").

f. Peek at a Codex worker

  1. PeekCache::refresh(flow) -> peek::transcript_of(flow, claude_home): (rollout, Format::Codex)
  2. PeekCache -> peek::tail(file, max, Format::Codex) -> peek::codex::parse
  3. No session yet, no file, or a .jsonl.zst rollout: an empty peek.

6. Conventions followed

  • codex::hooks mirrors claude_code::report_hooks (src/adapter/claude_code.rs:61): one synchronous handler per event, running the flow binary, with a 10 s timeout.
  • The wiring is spliced after the program, as in pane::worker_spec (src/launch/pane.rs:79) and MasterRecord::spec (src/server/master.rs:113).
  • Stop's exit 2 is the existing Document::Wake that flow wait returns (src/cli/commands/wait.rs:31).
  • News bookkeeping stays in deliver.rs and waits/. master_news_now is master_news (src/deliver.rs:44) without its settle pause.
  • File layout follows CLAUDE.md Structure:
    • one responsibility per file;
    • foo.rs beside foo/;
    • the peek parsers and the shared adapter helpers split along real seams;
    • server work lives in its own child file of impl Server, as conn.rs and panes.rs do.
  • The dialog's agent row copies its type row, in src/ui/newflow.rs and newflow/view.rs.
  • Deviation: the server writes into a PTY on its own, which HANDOVER rejected for Claude. It is limited to adapters that cannot wake themselves, and guarded by busy and quiet.
  • Deviation: the Claude master gets master.md as text through --append-system-prompt instead of -file, so both harnesses take instructions one way.

  • tests/cli.rs: flow hook codex on Stop exits 2 with pending news and 0 without. --master writes master.session.

8. Assumptions

  1. Codex's SessionEnd reason is always "other", so a Codex worker never logs ended from a hook. You end it with C-space Q or flow remove.
  2. Plan-mode and async questions are invisible to hooks. They read as working until Stop.
  3. plan-progress is a Claude Code mod, so a Codex worker shows no task bar.
  4. A .jsonl.zst rollout shows an empty peek.
  5. VIEW_VERSION stays 2 and PROTOCOL_VERSION goes to 4.
  6. The agent row lists every agent but master, and shows only with two or more.
  7. A paste of more than 1000 chars shows as a placeholder in Codex's composer and is still sent whole.

9. Decided in review

  1. The agent-skills get linked into ~/.agents/skills. Their content stays agent-agnostic.
  2. Codex is signed in. Fixtures are recorded from the real CLI, ideally after updating it from 0.144.1 to 0.163.0.
  3. E2E runs use a scratch FLOW_HOME.
