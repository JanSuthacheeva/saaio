Branch names that follow a project's convention

Decided: a repo names its branch template once; flow names the branch right at flow start (no rename later), with a {type} picked per flow in flow start --type and in the new-flow dialog.

1. What a project commits

# <repo>/.flow/config.toml (beside .flow/setup and .flow/teardown)
[branch]
name  = "{type}/{ticket}-{slug}"            # {type} {ticket} {slug} {name}
types = ["feature", "bugfix", "hotfix", "chore"]   # the first is the default
requesttypebranch
SHOP-217 add CSV exportfeaturefeature/SHOP-217-add-csv-export
SHOP-230 fix totals on refundsbugfixbugfix/SHOP-230-fix-totals-on-refunds
rate-limit the export endpointfeaturefeature/rate-limit-the-export-endpoint (no ticket: the separator next to it goes too)
no .flow/config.toml-flow/shop-217, as today

The worktree folder stays .flow/worktrees/<flow name>; only the branch changes. A branch that already exists gets -2, -3 like flow names do.

2. Where you pick the type

new flow in ~/projects/shop request ╭──────────────────────────────────────────────────────────────────╮ │ SHOP-230 fix totals on refunds │ ╰──────────────────────────────────────────────────────────────────╯ type ( ) feature (•) bugfix ( ) hotfix ( ) chore mode (•) auto ( ) guided guided stops at every phase creates bugfix/SHOP-230-fix-totals-on-refunds · slot 2 ───────────────────────────────────────────────────────────────────── enter start tab next field esc cancel

The type row only shows in a repo with types. flow start "..." --type bugfix does the same from the CLI (the master uses it); a type the repo does not list fails with the list.

3. Units

// src/branching.rs (new): a repo's branch convention
#[derive(Debug, Clone, PartialEq, Deserialize)]
pub struct Branching { pub name: String, #[serde(default)] pub types: Vec<String> }
impl Branching {
    /// <repo>/.flow/config.toml's [branch]; None without the file or the section.
    pub fn load(repo: &Path) -> Result<Option<Branching>>;
    /// The type a flow gets: `asked` when the repo lists it (an error naming the list when not),
    /// else the first listed; None when the repo has no types.
    pub fn pick_type(&self, asked: Option<&str>) -> Result<Option<String>>;
}
/// The branch for a flow: the template filled, empty placeholders' separators dropped;
/// flow/<name> without a convention.
pub fn branch_name(branching: Option<&Branching>, kind: Option<&str>, request: &str, name: &str) -> String;

// src/launch.rs
pub fn ticket(request: &str) -> Option<&str>;        // SHOP-217 as written (ticket_key lowercases it for names)
pub fn slug(request: &str) -> String;                // up to 5 words after the ticket, lowercase, -joined
pub fn workspace_for(repo, name, branch: String, slot, agent) -> Workspace;   // takes the branch now

// src/workspace.rs
pub fn branch_exists(repo: &Path, branch: &str) -> bool;

// src/main.rs
Start { .., /// Branch type from the repo's .flow/config.toml [[default: its first]]
        #[arg(long = "type")] kind: Option<String> }
// start: Branching::load(repo) -> pick_type(--type) -> branch_name -> -2, -3 while branch_exists -> workspace_for

// src/ui: NewFlowForm gains `branching: Option<Branching>` and `kind: usize` (a Type field between
// Request and Mode); Effect::LoadBranching(repo) when the dialog opens, answered by App::on_branching;
// Job::Start passes --type; the preview shows branch_name(..).

4. Call chains

  1. flow start "SHOP-230 fix totals" --type bugfix -> main::start -> Branching::load(repo): Some -> pick_type(Some("bugfix")): Some("bugfix") -> branching::branch_name(..): "bugfix/SHOP-230-fix-totals" -> workspace::branch_exists? -> launch::workspace_for(repo, name, branch, slot, agent) -> create_worktree
  2. Errors: a broken config.toml or an unknown type fail before anything is created (exit 1, help lists the types); --type in a repo without types fails the same way.
  3. Dialog: n -> App opens NewFlowForm -> Effect::LoadBranching(repo) -> ui::run reads it -> App::on_branching(Ok(Some(b))) -> type row + preview; Enter -> Job::Start(form) -> flow start ... --type <picked>. A broken file shows its error under the request, like a failed start.

5. Assumptions

  1. {ticket} keeps the key as written (SHOP-230); {slug} is up to 5 words after it, lowercased.
  2. An empty placeholder drops the -/_ next to it, so no feature/-x.
  3. The first listed type is the default; the dialog starts on it.
  4. Only the branch follows the convention; flow names and worktree folders stay as they are.
  5. A taken branch gets -2, -3, checked against local branches.
  6. Unknown keys in [branch] are an error, so a typo shows.

6. Tests

  • branching: load (none, section, broken, unknown key), pick_type, branch_name for the table above.
  • launch: ticket and slug.
  • tests/cli.rs: a repo with the file gets bugfix/SHOP-1-... with --type bugfix, the default without; an unknown type fails and creates nothing; a taken branch gets -2.
  • newflow: the type row only with types, tab order, the preview, Job::Start args.
