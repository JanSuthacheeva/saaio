saaio update design

The units, signatures and call chains for the update notice and saaio update. No bodies.

1. Decision recap

The UI checks a VERSION release asset through curl on its own thread, at most once a day across every UI on the machine (update.json in the shared folder). release.yml stamps SAAIO_RELEASE=<tag> into release builds, so saaio update knows a source build and names the cargo install line instead of replacing it.

Chosen: 1A, 2A. The user delegated every later decision to the recommendations below.

src/release.rs - new

What a release is: its tag, and the build this binary is (release or source).

pub mod source;

/// A release's tag, v0.1.1 or v0.1.2-rc.1.
pub struct Tag { version: semver::Version }
impl Tag {
    pub fn parse(text: &str) -> Result<Tag>;      // "v0.1.1" or "0.1.1"; else an error naming it
    pub fn version(&self) -> &semver::Version;
}
impl Display for Tag;                                // v0.1.1
impl Ord for Tag;                                    // semver: 0.1.1-rc.1 < 0.1.1 < 0.1.2

/// What this binary is: built by release.yml from a tag, or from source.
pub enum Build { Release(Tag), Source(semver::Version) }
impl Build {
    pub fn running() -> Build;                       // from env!("SAAIO_RELEASE"), else CARGO_PKG_VERSION
    fn of(stamp: &str, package: &str) -> Build;     // pure, for tests
    pub fn version(&self) -> &semver::Version;
}

src/release/source.rs - new

Where releases are read: GitHub's releases page, or a folder laid out like it (SAAIO_RELEASES_URL), through curl.

pub const GITHUB: &str = "https://github.com/JanSuthacheeva/saaio/releases";

pub struct Releases { root: String }
impl Releases {
    pub fn at(root: Option<String>) -> Releases;     // GITHUB unless set and non-empty
    /// <root>/latest/download/<asset> or <root>/download/<tag>/<asset>.
    pub fn url(&self, tag: Option<&Tag>, asset: &str) -> String;
    /// The tag in the latest release's VERSION; Err offline, past `limit`, on a 404 or a bad tag.
    pub fn latest(&self, limit: Duration) -> Result<Tag>;
    /// An asset's text: a release's install.sh.
    pub fn fetch(&self, tag: &Tag, asset: &str, limit: Duration) -> Result<String>;
    /// True for GITHUB: curl then insists on https and TLS 1.2, as install.sh does.
    fn is_github(&self) -> bool;
    /// What install.sh needs besides SAAIO_VERSION: SAAIO_DOWNLOAD_URL for a root that is not GITHUB.
    pub fn install_env(&self, tag: &Tag) -> Vec<(String, String)>;
}
fn curl(&self, url: &str, limit: Duration) -> Result<String>; // -fsSL, --max-time, process::output

src/update.rs - new

When to ask again, what the last answer was, and what saaio update does with a tag (pure, apart from the file).

pub const EVERY_MS: u64 = 24 * 60 * 60 * 1000;
pub const FILE: &str = "update.json";

/// The last look: when, and the latest tag it or an earlier look found.
#[derive(Serialize, Deserialize)]
pub struct Checked { pub at: u64, pub latest: Option<Tag> }

/// update.json in the shared folder.
pub struct UpdateCheck { file: PathBuf }
impl UpdateCheck {
    pub fn in_folder(registry: &Path) -> UpdateCheck;
    pub fn last(&self) -> Option<Checked>;               // None when missing or unreadable
    pub fn due(&self, now: u64) -> bool;                  // no look in the last EVERY_MS
    /// Records a look at `now`; a None answer keeps the latest an earlier one found.
    pub fn record(&self, now: u64, latest: Option<Tag>) -> io::Result<()>;
}

/// "0.1.1 is out: saaio update" when `latest` is newer than the running build.
pub fn notice(running: &Build, latest: &Tag) -> Option<String>;

/// What saaio update does.
pub enum Step { Latest, Source, Unwritable, Install }
pub fn step(running: &Build, target: &Tag, asked: bool, writable: bool) -> Step;

5. Call chains

The UI starts, and every hour while it runs

  1. ui::run -> UpdateWatch::new(env.update, env.releases, Build::running())
  2. reload_config -> UpdateWatch::set_enabled(config.ui.update_check); off: App::set_update(None), no look
  3. ui::run -> App::set_update(watch.notice()): the last answer from update.json, no network
  4. ui::run -> UpdateWatch::ask_if_due(now, &events) at start and each TICKS_PER_UPDATE
  5. UpdateWatch -> UpdateCheck::due(now): false -> done
  6. UpdateWatch -> UpdateCheck::record(now, None) first, so a second UI does not ask too
  7. thread: Releases::latest(LIMIT) -> curl .../latest/download/VERSION -> Event::Latest(Some(tag))
  8. ui::run -> UpdateWatch::answered(now, latest) -> UpdateCheck::record; App::set_update(watch.notice()) redraws

Errors: offline, timeout, 404, no curl, unreadable or unwritable file -> Event::Latest(None) or nothing; the notice stays as it was. Nothing is logged and nothing shows.

saaio update [--version TAG]

  1. cli::run -> commands::update::run(args, env), before the store is opened
  2. run -> Tag::parse(version) or env.releases().latest(15 s)
  3. run -> current_exe().canonicalize(), its folder; rustix::fs::access(dir, WRITE_OK)
  4. run -> update::step(Build::running(), tag, asked, writable)
  5. Latest -> output::update::latest, exit 0
  6. Source -> output::update::source: the cargo install line with the tag, exit 1
  7. Unwritable -> output::update::unwritable: curl ... | sudo env SAAIO_VERSION=.. SAAIO_INSTALL_DIR=.. sh, exit 1
  8. Install -> Releases::fetch(tag, "install.sh") -> sh -s with SAAIO_VERSION, SAAIO_INSTALL_DIR and Releases::install_env -> install.sh downloads, verifies SHA256SUMS, renames over the binary
  9. output::update::updated(from, to, binary)

Errors: a bad --version -> exit 2 usage-style message naming it; latest unreachable -> exit 1 "could not read the latest release: <curl's line>", help: check the connection or pass --version; install.sh fails (checksum mismatch, no prebuilt binary for the platform) -> exit 1 with its last line.

6. Conventions followed

  • A thread whose answer comes back as an Event: run_job, src/ui.rs:270.
  • Commands without a store: BugReport, src/cli.rs:86.
  • A build input passed through build.rs: SAAIO_COMMIT.
  • Shared-folder files written through private::write_atomic: slots.rs, registry.rs.
  • Processes with a deadline: workspace/process.rs:16; config defaults with a manual Default: ServicesConfig.
  • One deviation: a new dependency, semver (dtolnay, no dependencies of its own), for correct pre-release ordering instead of a hand-written comparison.

7. Test seams

  • release.rs: Tag parse and ordering, Build::of; unit.
  • release/source.rs: URLs; latest and fetch against a file:// folder; a missing folder errs.
  • update.rs: due, record keeping an earlier tag, notice, the step matrix; unit with a temp folder.
  • update_watch.rs: disabled shows nothing; an answer sets the notice; ask_if_due sends Latest from a fake folder.
  • chrome: golden files for the update line with the sidebar, with the rail, and dropped when narrow.
  • commands/update.rs install: the real install.sh against a fake release folder (tarball, SHA256SUMS), replacing a binary in a temp folder; a bad checksum fails.
  • tests/cli/update.rs: a source build names the cargo line; the latest unreachable fails with help; --version nonsense fails.
  • config: the example test covers #update_check = true.

8. Assumptions

  1. A failed look counts as the day's look, so an offline laptop does not try every hour.
  2. The notice only shows; no key dismisses it. It goes when saaio is updated and the UI restarted.
  3. saaio update with no newer release does nothing; --version installs that tag even if it is older or the same.
  4. A source build is never replaced by a release binary, even with --version.
  5. The notice is on for source builds too.
  6. SAAIO_RELEASES_URL is public and documented as a mirror of the releases page, which is also the test fake.
  7. The title shows 0.1.1 is out: faint and saaio update in the key color, and drops first when the row is short.
  8. The ROADMAP row is removed, as it ships in this PR.
