Typed lines: implementation

flow send --type <flow> <line> queues a line in the flow's log. The server types it and Enter into the worker's pane once the session is idle, one line per turn, in order.

1. Decision recap

Approach A: a new Typed { text } event is the queue, waits/<id>.typed counts the lines typed, and a new Server::type_lines types the next one when the pane is ready. Both harnesses mark turns in waits/<id>.busy, so "idle" means the same for Claude Code and Codex.

  • Decided: approach A, one line per call (flow send --type shop-217 /compact, then flow send --type shop-217 "continue shipping").

server/typing.rs

new · server · the master's queued lines, typed into idle panes

/// How long a typed line may go without a turn beginning before the next one may follow:
/// a command such as /cost runs no hook.
const UNSTARTED: Duration = Duration::from_secs(30);   // 300 ms in tests

impl Server {
    /// Types each flow's next queued line into its pane when the pane is ready, and lets a line
    /// that began no turn within UNSTARTED go.
    pub(super) fn type_lines(&mut self);

    /// Pastes `text` and Enter into the pane, marks the session Busy::Typed and when; news and
    /// queued lines both type through it.
    pub(super) fn type_into(&mut self, key: &PaneKey, waiter: &Waiter, text: &str) -> Result<()>;

    /// The flow whose queued lines this pane takes: a running worker of a flow that is not plain
    /// or finished, whose agent has an adapter and whose session ended a turn (answer set).
    fn takes_lines(&self, key: &PaneKey) -> Option<String>;
}

/// True when the pane takes a line now: idle, open and untouched by the person for QUIET.
fn ready(busy: Busy, opened_at: Option<Instant>, typed_at: Option<Instant>, now: Instant) -> bool;

/// True when the server's own typed line began no turn within UNSTARTED.
fn unstarted(busy: Busy, line_at: Option<Instant>, now: Instant) -> bool;

5. Call chains

The master queues a line

master      send::run          fold / wake         Store
  | --type ---->|                   |                  |
  |             |-- views --------> |                  |
  |             |-- resolve ------> |                  |
  |             |   refusals        |                  |
  |             |-- untyped ------> | (ahead)          |
  |             |-- append Typed ---------------------->|
  |<- queued ---|                   |                  |
  1. cli::run -> send::run(args, store, config, env.flow_id(), now): Result<Document, Failure>
  2. send::run -> views(store, now), fold::resolve(&flows, &args.flow): Option<&FlowView>
  3. Refusals in order: sender set, empty, too long, a newline, no flow, finished, no worker, plain, agent without adapter (config.agent(Some(&workspace.agent))).
  4. send::run -> store.events(id), wake::untyped(&events, store.typed(id)).len(): usize (ahead)
  5. send::run -> store.append(id, Event::new(now, Typed { text }))
  6. send::run -> output::flow::queued(flow, text, ahead): Document

Errors: each refusal is a Failure with its help, exit 1. A newline: "a typed line is one line", help "Queue one `flow send --type` per line". No adapter: "<name> runs <agent>, which reports no turns to flow", help "Use `flow send` for a message".

The server types the next line

serve      type_lines         Store            Host (PTY)
  | tick ---->|                  |                  |
  |           |-- takes_lines    |                  |
  |           |-- busy --------->|                  |
  |           |   ready?         |                  |
  |           |-- events, typed ->|                 |
  |           |   wake::untyped  |                  |
  |           |-- type_into ------------------------>| paste + \r
  |           |-- set_busy(Typed)>|                 |
  |           |-- set_typed(n+1)->|                 |
  1. Server::serve -> Server::type_lines() every WATCH_EVERY, after deliver_news
  2. For each running pane: takes_lines(&key): Option<String>
  3. type_lines -> store.busy(&waiter): Busy. If unstarted(busy, line_at, now): store.set_busy(&waiter, Busy::Idle), log "no turn began after typing into <name>", and go on as idle.
  4. ready(busy, opened_at, typed_at, now) false: skip this pane.
  5. store.events(id), store.typed(id), wake::untyped(&events, typed).first(): none, skip.
  6. type_lines -> type_into(&key, &waiter, line): host.write(&key, &paste(line)), store.set_busy(&waiter, Busy::Typed), line_at.insert(key, now)
  7. type_lines -> store.set_typed(id, typed + 1)

Errors: a failed write is logged to server.log and the count is not raised, so the line is tried again next tick. A failed set_typed is logged; the line could be typed twice, as a failed set_delivered today could deliver twice.

The worker runs the line and comes back idle

harness         flow hook           Store
  | UserPromptSubmit / PreCompact ->|  set_busy(Turn)
  |   ... the turn or the compaction ...
  | Stop / PostCompact ------------>|  set_busy(Idle)   (Codex: hand_over first)
  1. hook -> adapter.turn(payload): Some(Turn::Began) -> mark_busy(store, &waiter, Busy::Turn)
  2. hook -> adapter.turn(payload): Some(Turn::Ended): adapter.wakes_itself() -> mark_busy(.., Busy::Idle); else hand_over as today, Idle when there is no news.
  3. The next tick's type_lines sees Idle and types the next line after QUIET rules.

Esc on Claude Code runs no hook: the mark stays Turn until the next prompt's turn ends. A line that starts nothing (/cost): Typed for UNSTARTED, then Idle (step 3 above).

flow wait wakes a Claude Code worker

  1. wait::wait -> deliver::worker_news(store, id, now): WorkerNews::News
  2. wait::wait -> store.set_busy(&waiter, Busy::Turn), then returns the news (exit 2 wakes the session)
  3. That turn's Stop marks Idle.

6. Conventions followed

  • Typed and .typed mirror Message and .delivered (event.rs:68, store.rs:231, wake.rs:19).
  • Refusals and their help copy send.rs:23-60; the answer is a document in cli/output/flow.rs beside sent.
  • Typing copies server/news.rs: one bracketed paste and \r, QUIET after a person's key, cfg(test) constants.
  • One file per responsibility (CLAUDE.md): typing.rs is "the master's lines typed into panes", news.rs stays "news typed into Codex panes".
  • Earlier master.md defaults kept as master-vN.md (server/master.rs:21).
  • Deviation: Store::busy returns an enum instead of a bool, since the server must tell its own mark from a turn's.

8. Assumptions

  1. The worker sees a typed line as the user's prompt, unmarked: it is what you would have typed.
  2. A line is typed only after the session ended a turn at least once (its flow has an answer) and its pane has been open for 10 s, so nothing lands in a harness still starting up or resuming.
  3. A line that begins no turn holds the queue 30 s, then the next goes.
  4. Queued lines of a flow wait while no server runs, and are typed once flow ui opens its pane.
  5. No way to drop a queued line. Removing the flow drops them.
  6. No typing into the master's pane: flow send names a flow.
  7. The CHANGELOG is untouched (0.1.0 is not released, so nothing gets an entry). ROADMAP has no item for it.
  8. Compaction changes no flow state: the sidebar shows the worker idle while it compacts.

9. Open questions
